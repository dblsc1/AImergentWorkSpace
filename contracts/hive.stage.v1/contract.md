## 一、布局（规范性）

设计宽度 1280px；1024–1279 宽按比例缩小同一布局；< 1024（含手机）本版不支持，以后做列表。

| 位置 | 放什么 | 数据 |
|---|---|---|
| 中间 | 蜂巢：每个项目一个格子，按分区分组。**格子上只有项目名** | 任务树 |
| 蜂巢正中心 | 聚焦代理的计时环（代理名 + 本次已用时间） | 「二」1 |
| 右上角 | 人的时钟：今天已记时长 + 当前项目名；一个气泡停在人所在项目的格子旁；时钟下方是上下缓慢浮动的白条 | 「二」2、「三·1」 |
| 格子边 | 干活的宠物，至多 4 只 | 「二」3 |
| 左上角 | 没有去向的代理宠物，慢慢踱步 | 「二」4 |
| 左下角 | 「未分类」桶：`未分类 · 今天 X 小时 Y 分`（不足 1 分钟写 `未分类 · 今天 0 分`） | 「二」5 |

- 计时页（`/timer`）并入蜂巢页；旧地址 `302` 到 `/hive/`（临时跳转，保留以后改）。
- 决策栏照旧在页面上（只剩 AI 提议，见 `onboarding.v1`「八」）。

## 二、各部分的规则（规范性）

1. **中心计时环**：取 v2.17 `attend` 里人此刻在看的那条运行（`attend` 最后一条的 `until` ≥ 此刻 − 15 秒算此刻在看）；人没在看任何代理 → 今天最后看过的那条；今天没看过 → 空环。「今天」= NEXUS_TZ 本地日。
   人换着看别的代理时，环换成那条运行，过渡 ≤ 600ms。
2. **右上角时钟**：今天人的记录时长合计（手动计时 + 自动入账），读 `GET views/lanes`（今天）的 `human.sessions` 与 `human.running`，裁到今天后求和。v2.16 `focus` 认出项目时，气泡停在该项目格子旁；
   项目变了，气泡沿弧线飞到新格子（约 600ms）；`focus.state: "afk"` 或认不出时，气泡回到时钟上。
   **手动计时**（离开电脑的事用它）：
   - 点时钟 = 立刻开始计时（`POST timer/start-unplaced`，「三·1」），不用选项目；再点 = 停（既有 `POST timer/stop`）。
   - 计时中把时钟（或它的气泡）拖到某个格子 = 这次计时记到该项目（`POST timer/place`）。已在计时时又拖到另一格 = 改记到新格子，不新开一段。
   - 停下时还没记到项目的，变成一条白条，在右上角时钟下方上下缓慢浮动；拖白条到格子 = 记到该项目（`POST timer/unplaced/{id}/place`）。多条白条按时间排，至多显示 5 条，多的显示 `+N`。
   - 放到空白处 = 回原位，什么都不改。
3. **干活的宠物**：此刻在跑、挂了任务或项目的运行，每条一只，停在它项目格子的边上，播 `working` / `waiting` / `idle` 动作（`desktop.pet.v1`「一」的 mood）。
   - 动作由运行的 `phase` 定：`working` → `working`，`waiting_input` / `waiting_permission` → `waiting`，`idle`、`error`、失联 → `idle`。
   - 至多 4 只，按最近活动时间（`views/lanes` 的 `agents[].lastSeenAt`，为 `null` 取 `startAt`）从新到旧取，并列按 `runId` 升序；其余在蜂巢边显示一个 `+N`。
   - 用哪个宠物包：按运行的 `tool` 查「宠物包对照」（`desktop.pet.v1`「三」）；查不到用 `*` 对应的包（缺省 `deepseek`）。
   - 只显示宠物与名牌（`label` 或 `agent`）；明细在点开格子后看。
4. **左上角：没有去向的代理**：此刻在跑、`taskId` 与 `projectId` 都没有的运行，每条一只，在左上角区域慢慢随机走动；最多 4 只，多的显示 `+N`。
   走动由可注入的随机源与时钟驱动；位置始终在左上角区域内，每步位移 ≤ 速度 × 时间。
   拖一只进格子 = `POST agents/{runId}/place {projectId, remember: true}`（「三」）；成功后宠物飞到该格子边，提示「已记下：以后 <agent> 都算 <项目名>」，3 秒后消失。
   放到空白处 = 回原位，什么都不改。
5. **左下角桶**：今天（NEXUS_TZ 本地日）「未分类」窗口时间合计。点桶展开抽屉：`legible` 的块按秒数排，可拖；看不懂的按「浏览器（其他网站）」「终端（未认出）」「其他」合成灰色行，不能拖。
   拖块进格子 = `POST activity/blocks/assign {date, blockKey, ifSeq, projectId, remember: true}`；成功后块从抽屉消失、桶上时长减少，提示「已记下：以后 <displayName> 都算 <项目名>」。
   **拖到分区的空白处 = 建新项目**（仓主 2026-11-08 定，同 #166）：经过空白处时长出与「空白处长按建项目」完全相同的那一格、同样的升起与颜色浮现动效；放下后走同一张建项目确认；建好后把这个块记进新项目（`blocks/assign`，`remember: true`）。离开空白处或取消 = 收掉那一格、块回原位。拖到分区以外 = 回原位。
   - 2026-11-08 起（追加）：点灰行（鼠标或回车 / 空格）在抽屉旁弹出该类的窗口列表，再点收起；一块（`blockKey` = 程序 · 归一化标题）= 一组同名窗口，一行：标题（`blockKey` 去掉程序名前缀，没有标题就写程序名）+ 分钟，按秒数降序。每行与可拖块一样：拖进格子 = `POST activity/blocks/assign {…, remember: true}`（记下这个块名的规则），拖到空白处 = 建新项目（「8」）；提示里的名字是「程序 · 标题」。分走后该行消失，列表空了就收起。灰行本身仍不能拖。不新增接口。
6. **拖动**：原生 Pointer Events，鼠标、触控板都能拖。拖动中目标格子高亮；失败（`409` / `422` / 网络）时被拖物回原位并提示原因。
7. **点宠物、拖宠物**（仓主 2026-11-08 定，参照 dsh-pet 0.4.5）：格子边与左上角的宠物都能点、能拖。
   - 只认主键（左键 / 单指）。按下后移动 < 5px 松手 = 点；≥ 5px = 拖。拖完松手后 100ms 内的点不算。
   - **点**：从宠物包 `moods.click` 随机挑一段播一次，不挑刚播过的那段；同时压扁再弹回（纵向压到 0.55，220ms）。播完回到原来的动作。包里没有 `click` 用 `happy`；占位形象只压扁弹回。
   - **拖**：跟手移动，播 `moods.drag`（没有就保持原动作）。拖动中不随轮询换位置、不换动作。
   - **格子边的宠物松手**：不改任何数据（不改去向）。原地停 3 秒（让人看清、点到下面的项目名），再播 `moods.walk`（没有就保持原动作）以 45px/s 走回它在格子边的位置，单程至多 8 秒（远了就加快）；朝着走的方向（动画朝左，往右走时水平翻转）。到了恢复原动作。
     停留或走回途中被点 = 照「点」播一次后接着走；又被拖 = 重新计时。期间它的运行结束或换了格子 = 直接走向新位置或消失。
   - **左上角的宠物松手**：落在格子上 = 照「4」建去向规则；落在空白处 = 从落点接着随机走动（不走回）。
   - `prefers-reduced-motion`：不压扁、不走，3 秒后直接回到原位。
   - Esc 取消拖动 = 立刻开始走回（左上角的从原位接着走）。
8. **所有「时间元素」拖到空白处建项目**（仓主 2026-11-08 定）：抽屉里可拖的窗口块、宠物（左上角的与格子边的）、计时中的时钟气泡、白条，拖到分区的空白处并**停住**：
   - 停住的那一格与「空白处长按建项目」同一格、同样的升起；颜色**慢慢亮起**，时长与长按建项目的显现同一个数（`LONGPRESS_MS` = 520ms，`prefers-reduced-motion` 下立刻亮满）。
   - 亮满之后松手 = 打开同一张建项目确认；建好后把这个元素记进新项目：块 `POST activity/blocks/assign {…, remember: true}`；宠物 `POST agents/{runId}/place {projectId, remember: true}`；计时中的气泡 `POST timer/place {projectId}`；白条 `POST timer/unplaced/{id}/place {projectId}`。
   - 没亮满就松手、离开空白处、Esc、取消表单 = 那一格收掉，什么都不建，元素回去（格子边的宠物照「7」走回；左上角的宠物从落点接着走动）。
   - 2026-11-08 起：宠物与白条拖到空白处不再只是「回原位」；本条覆盖「二·2」「二·4」「二·7」里「放到空白处 = 回原位 / 从落点接着走动」在**停住并亮满再松手**这一种情况上的说法，没亮满就松手仍照原文。
   - 没在计时时，时钟与气泡拖到空白处什么都不发生。
9. **白条的点与标签**（仓主 2026-11-08 定）：
   - 点白条（移动 < 5px）= 在白条旁弹出一个小项目列表：按分区分组列出项目；项目多于 8 个时带搜索框；键盘上下选、回车确认、Esc 关闭；点列表外也关闭。选中某个项目 = 与把这条白条拖到那一格发同一个请求（`POST timer/unplaced/{id}/place`）。
   - 每条白条左侧有一行文字标签：「手动计时 · <HH:MM 开始> · <X 分钟>」；这段计时带标题 / 名字时改为「手动计时 · <标题> · <X 分钟>」。单行，太长用省略号。

## 三、代理去向（规范性，nexus-core v2.44）

`POST /api/core/agents/{runId}/place`（只许人；带 Bearer 的设备令牌 `403`）

```jsonc
{ "taskId": "t_…" | "projectId": "p_…",   // 恰好一个
  "remember": true }                        // 缺省 true：同时写（或替换）一条代理去向规则
// 200 → { "runId": "run_…", "taskId": null, "projectId": "p_…", "rule": { "agent": "garden", "projectId": "p_…" } | null }
```

- 整条运行（从开始算）改挂到这个目标：追加事件 `agent.run.placed`（`data: {runId, taskId?, projectId?, at}`），投影按最后一条算（重建后一致）；读投影（`views/lanes`、`views/agent-time`、按天统计）按新目标重算这一条。已结束的运行也可以 place。运行不存在 `404`；目标不存在 `404`。给 `taskId` 时响应里的 `projectId` = 任务所在项目。
- **代理去向规则** `agent_place_rules {user, agent, taskId?, projectId?, createdAt}`，`(user, agent)` 唯一，至多 500 条（超了 `422`，什么都不改；替换已有的 `agent` 不算超）。规则的 `agent` 为空串 `422`。
  以后 `agents/start` **没给** `taskId` / `projectId` 时，服务端按 `agent` 完全相同查这张表，查到就挂上。给了的照旧以给的为准。规则的目标后来被删：当没有规则处理，运行不挂目标，不报错。
- `GET /api/core/agents/place-rules`（人与 MCP；设备令牌 `403`）→ `{items: [{agent, taskId, projectId, createdAt, broken}]}`，目标已删的 `broken: true`；`DELETE /api/core/agents/place-rules/{agent}`（只许人）删一条，不存在 `404`，已挂上的运行不动。`{agent}` 按 URL 百分号编码，服务端解码后精确比较。
- 进导出 / 恢复。

### 三·1 无项目计时与白条（规范性，nexus-core v2.44）

既有端点（nexus-core 契约「对外 API」）：`POST timer/start {taskId}`（必须带任务）、`POST timer/stop`、`POST timer/cancel`、`POST timer/backfill {taskId, startAt, durationSeconds}`、`POST planner/projects/{id}/unclassified → {taskId}`（项目的「未分类」桶，取或建）。
它们做不到「不带项目开始计时」「计时中改记到项目」「事后给一段计时补项目」，所以追加下列端点；**只许人**，设备令牌与 MCP `403`。

- `POST /api/core/timer/start-unplaced`（无体）→ `200 TimerOut`，`taskId: null`、`projectId: null`。已在计时 `409`。
- `POST /api/core/timer/place`
  ```jsonc
  { "taskId": "t_…" | "projectId": "p_…" }   // 恰好一个
  // 200 → TimerOut（目标已换成新的）
  ```
  把在跑的计时改记到该目标；`projectId` 记到该项目的「未分类」桶（取或建，同 `planner/projects/{id}/unclassified`）。在跑的计时已有目标时同样改记到新目标，不停、不新开一段。没在计时 `409`；目标不存在 `404`；两个都给或都不给 `422`。
- `POST timer/stop`（既有）：在跑的计时有目标 → 照旧写 `session.completed`；没有目标 → 不进台账，存一条白条 `timer_unplaced {user, id, startAt, endAt, createdAt}`。`TimerStopOut` 追加 `unplacedId`（有目标时为 `null`）。`timer/cancel`（既有）对无目标的计时同样是「不记录」。
- `GET /api/core/timer/unplaced` → `{items: [{id, startAt, endAt, durationSeconds}]}`，按 `startAt` 升序。
- `POST /api/core/timer/unplaced/{id}/place` `{taskId | projectId}`（恰好一个）：按白条的 `startAt` / `endAt` 写一条 `session.completed`（`source: "timer-backend"`，目标同 `timer/place`），删这条白条；`200 {recorded: true, taskId, projectId}`。白条不存在 `404`；目标不存在 `404`。允许与别的已记时间重叠（同 `timer/backfill`）。
- 白条进导出 / 恢复：导出顶层键 `timerUnplaced`（有白条才出现），每条只含 `id`、`startAt`、`endAt`、`createdAt`；恢复先校验后落库。
- 停止与改记同时发生时，以「改记」为准（停止只在条件删除抢到无目标的活状态时才存白条）。

### 三·2 代理去向的事件与投影（追加）

- 事件 `agent.run.placed`（只由服务端写；公开事件入口拒收这个类型与来源 `agent-place`），`data`：`{runId, seq, taskId, projectId, fromTaskId, fromProjectId, at}`；已结束的运行另带 `run`（该运行的起止与按天 `working` 秒数），投影据此搬运，不回查事件库。去重键 `place:<runId>:<seq>`；运行的当前去向取 `seq` 最大的一条。
- 投影搬运幂等（每行记已搬过的事件键）；原来没有项目的运行改挂到项目时只加到新行。重建与实时投影一致。
- 代理去向规则进导出 / 恢复：顶层键 `agentPlaceRules`，每条只含 `agent`、`taskId`、`projectId`、`createdAt`；恢复先整批校验（`agent` 非空不重复、≤ 500、目标键恰好一个）后落库。

### 三·3 只算以后的时间（追加，nexus-core v2.48）

`POST /api/core/agents/{runId}/place` 体追加可选 `timeFrom: "start" | "now"`，缺省 `"start"` = 上面的整条改挂（行为不变）。
`"now"`：此刻之前的时间留在原去向（含收件箱），此刻起的时间算新去向；只许正在跑的运行，已结束的 `422`（「只算以后的时间」只能用于正在运行的代理…），其余值 `422`。规则见 nexus-core 契约「v0.6：代理只算以后的时间（v2.48）」。

## 四、完成记录（规范性）

点格子弹出该项目的「完成记录」面板，可关。

- **左半边：人的时间**，两类，各一条时间线 + 合计，取今天（NEXUS_TZ 本地日），元素形状 `{from, to, kind}`：
  - 计时（`kind: "timer"`）：`GET views/lanes`（今天）`human.sessions` 里 `projectId` 命中该项目的段（`startAt` → `from`，`endAt` → `to`）；
  - 对话（`kind: "attend"`）：同一响应 `interactions` 里 `kind: "attend"`、`runId` 属于该项目下运行的条目（`at` → `from`，`until` → `to`）。
- **右半边：代理的时间**：该项目下每条运行一行：名字、`working` 秒数、当前状态；底部一格「token 花费」，本版显示「—」。
- 数据来自既有读端（`views/lanes`、`views/agent-time`）；本版不新增读端。

### 二·10 归档气泡与详情卡（2026-11-08 追加，仓主定）

本节只增不改；其中「宠物 / 块拖进格子」的请求与提示，仅在此处按 2026-11-08 的追加取代「二」5、6 里「`remember: true`」「提示『已记下：以后 … 都算 …』」两句，其余不动。

1. **默认只记这一次**：宠物（含灰行弹窗里拖出的窗口块）拖进格子，请求带 `remember: false`：宠物 `POST agents/{runId}/place {projectId, remember: false}`；块 `POST activity/blocks/assign {date, blockKey, ifSeq, projectId, remember: false}`。空白处建项目后的记入同样如此。旧提示「已记下：…」不再出现（失败提示照旧）。
2. **归档气泡**：落点（格子）旁弹一个气泡形小选框，最左一个转圈倒计时，5 秒，到了淡出消失；其后一个复选框，默认不勾：宠物「以后都算 <项目名>」，块「以后这个窗口都算 <项目名>」。勾上 = 再发一次同目标的请求，`remember: true`（块的 `ifSeq` 用上一次 `assign` 回的 `seq`，没有则 +1；`assign` 对已分类的块可重复发）。鼠标悬停或焦点在气泡内时倒计时暂停；`prefers-reduced-motion` 时不动圈，只是 5 秒后消失。同一时刻只一个气泡。手动计时的气泡、白条、时钟拖放不弹此气泡。
3. **点气泡**（复选框以外）= 打开详情卡，同点宠物。
4. **详情卡**：贴在宠物旁；写标题（全名）、工具与模型、归在哪个项目 / 任务、当前状态与今天的工作时长、最近几条状态变化、窗口线索（运行的 `match`）、一个改名输入框。回车保存：`PUT /api/core/agents/{runId}/name {"name": "…"}`（只许人；`null` 或空 = 清除）。Esc 或点卡外关闭。点宠物仍播放「二」7 的点击反应，同时开卡；再点一次收起。窗口块的详情卡改列该块的窗口（标题、分钟，读 `activity/blocks/records`）。
5. **宠物名牌**：`views/lanes` 的运行可带 `humanName`（人改的名）与 `conversation`（对话名），均可为 `null`。名牌 = `humanName`；否则有项目 / 任务时 `<任务或项目名>·<对话名>`；否则 `conversation`；`conversation` 为 `null` 时仍是 `label || agent`。名牌单行省略，全名在卡里和 `title` 提示里。工具、模型只在详情卡里。

### 二·11 宠物的位置、动作节奏、详情卡改版、挂到别的项目要确认（2026-11-10 追加，仓主定）

本节只增不改；与前文冲突处以本节为准：「二」4 的「随机走动」与 `hex-pet-pick` 的走动步进作废，「二·10」3 的归档气泡对宠物作废（块仍用气泡），「二·10」4 详情卡的「状态变化列表」「改名输入框」「今天的工作时长」被下面第 5、6 条取代。

1. **收件箱不算去向**：`views/lanes` 回来 `projectId = p_inbox`（系统收件箱）的运行，在本页一律当没有项目：名牌、详情卡（「还没归到项目」，不写「归在 收件箱」）、完成记录、归档提示都不出现「收件箱」。没挂项目的宠物名牌 = `humanName || conversation || label || agent`，不加项目前缀。只改前端，后端不动。
2. **左上角一只一个位**：不再随机走动。左上角区域按固定的位排布；已有位的宠物在轮询、重画时不动，新来的按（开始时间，`runId`）占最小的空位，走了的位留给后来的。拖动与「停 3 秒再走回」照旧：松手后走回自己的位。
3. **动作节奏**（每只宠物，格子边与左上角都一样）：当前 mood 的动作列表里随机播一段 15 秒，接着播 3 秒临时动作（宠物包 `click` 列表，没有用 `happy`，都没有就跳过这一步），再从 mood 列表里随机挑一段**与上一段不同**的（列表只有一段时就是它）播 15 秒，如此循环。短于时段的动作循环播放，由计时切断。mood 变了：立刻换成新 mood 的动作并重新计时。每只宠物的首个 15 秒随机错开。点击反应、拖动动作仍优先于节奏动作，结束后回到节奏当前该播的那段。调度是 `hex-pet-pick` 里的纯函数（随机源与时钟可注入）。
4. **改名直接点标题**：详情卡标题显示全名（折行，不省略）；点标题原地变输入框（预填 `humanName`，没有则预填当前标题，全选）：回车 = `PUT agents/{runId}/name`（空 = `null`，恢复自动名），Esc 或失焦 = 取消；轮询重画不打断；保存失败输入框标红。名牌（卡外）仍可省略。不再有单独的改名输入框。
5. **工作时间泳道**：详情卡里一行状态「<状态> · 近 3 小时工作 X 分钟」，其下一条横条覆盖最近 3 小时，按 `phases` 分段着色（工作中 / 等你 / 空闲 / 出错），段到下一条 phase 或此刻为止，运行第一条 phase 之前为空；下方刻度 3 小时前、2 小时前、1 小时前、此刻（`HH:MM`）；悬停一段提示 `HH:MM–HH:MM 状态`。卡开着时随轮询刷新。不再读 `views/agent-time`，也不再列状态变化。
6. **宠物拖到另一个项目要确认**：任何宠物（左上角的、已在格子边的）都能拖到别的项目格子上。松手后宠物留在落点等，格子旁弹确认卡（不是 5 秒气泡）：标题「把 <宠物名> 挂到 <项目名>」，两个按钮「之前的时间也算过去」「只算以后的时间」，一个复选框「以后 <宠物名> 都算 <项目名>」（默认不勾 = `remember: false`），和一个 ×。
   - 「之前的时间也算过去」：`POST agents/{runId}/place {projectId, remember}`（整条运行，同「三」）。
   - 「只算以后的时间」：同一请求，body 多一个 `"timeFrom": "now"`（缺省或 `"start"` = 整条运行；字段由 nexus-core 定义，本页只发送）。服务端回 `422`（旧服务端不认）按失败提示，宠物回原处。
   - 一次可以连续落下好几只，每只一张卡，互不取代；同一格子的卡在该格上方自上而下叠着，放不下时叠层滚动；不同格子的卡在各自格子旁。每只宠物在自己的卡答完或取消前留在落点。Esc 只取消最新一张；点卡外不取消；每张卡有自己的 ×。取消 = 什么都不发，宠物走回。
   - 宠物拖到自己所在的格子、空白处，不弹卡，照旧走回；块的气泡与白条不变。

## 七、项目面板 · 人/代理时间标尺（规范性，2026-11-10 追加，nexus-core v2.49）

仓主原话：「蜂巢任务格子，大体按B，左边是任务卡片，但是做成一长条。即卡片1-3纵列，左半部分是任务，右半是泳道式的花费时间统计，人和agent的不要做一左一右分开，做成上下半。右半最上是一条绝对刻度尺子，总计7天，前6天较窄占70%宽，第7天（当天）宽30%，对下去，对应3条泳道，人的时间在上（每天花费在上面的时间段，红色），下半是agent在这个任务上工作的时间，用对应项目色。这个编排可以作为项目通用的人/agent时间标尺表。」

点项目格弹出的面板（「四」的左人右代理两列取消，面板仍可关、仍有「展开」）：标题 = 项目名；其下是**标尺**与一列**任务条**。

- **任务条**：每个任务一条长横条，纵向排列，多了列表自己滚动；项目下所有任务各一条，末尾再加一条「没挂任务」（挂在项目上、没挂任务的时间）。条的左半是任务（名字，右下小字 = 这 7 天人 / 代理各多少），右半是这个任务的两条泳道。
- **标尺**：右半最上，一条绝对刻度，所有任务条共用同一个横向刻度（对齐）。共 7 个本地日（NEXUS_TZ 的日界取浏览器本地日）：前 6 天（今天之前的 6 天）等宽共占 **70%**，今天占 **30%**；过去的天标周几，今天标「今天」并在其 30% 里标 00 / 06 / 12 / 18 / 24 钟点刻度。位置是时间到横坐标的分段线性映射，天与天交界处连续，所以跨零点的段仍是一条。
- **泳道**：上下两半（不是左右）。上半 = 人在这个任务上的时间，红色（`--pr-human`，亮 / 暗两套主题各一个值）；下半 = 代理在这个任务上的**干活**时间（working 相位，口径同 `views/agent-time`），用项目所在分区的颜色（`--pr-agent`）。段是真实区间 `[start, end)`，不是按天合计；过去的天被压得很窄，段再短也至少 1px 可见。
- **悬停**一段：提示 `MM/DD HH:MM–HH:MM 你`（人）或 `MM/DD HH:MM–HH:MM <代理名>`（代理名 = 人起的名字，否则运行标签，再否则代理键）。
- **数据**：`GET /api/core/views/project-time?projectId=&from=&to=`（nexus-core v2.49，只读），`from` = 6 天前、`to` = 今天（本地日期）；每 5 秒随面板重读。任务名来自 `views/tree`，分区色来自 `views/tree` 的 `zones[].color`。
- **复用**：标尺是纯函数加渲染（`hex-project-ruler.js`：`layout` 定 7 天刻度，`xOf` / `spanRect` 把时间戳换成 0..1 的位置，`rulerHtml` / `lanesHtml` 画标尺与泳道），别的页面要画「项目通用的人 / 代理时间标尺表」直接用，不必经过面板。
- **拖动**（仓主 2026-11-10：「拖入任务先这样：拖到哪个就算哪个，也可以拖到展开，保持1秒，就自动展开。拖动的时候长按就等于点击。新建项目/任务也都是。拖动到对应项目要有颜色变深的效果。」）：
  - 拖着任一时间元素（代理宠物、窗口块、时钟 / 气泡、计时白条）经过项目格，该格**变深**（落点）；松手 = 记到项目（「二」原行为）。
  - 在项目格上**停住 1 秒**（指针移动不超过约 10px）= 等于点击：面板弹开（弹簧展开）。面板里指针下的任务条同样变深；松手在任务条上 = 记到**这个任务**：代理 `POST agents/{runId}/place {taskId}`，窗口块 `POST activity/blocks/assign {taskId}`，白条 `POST timer/unplaced/{id}/place {taskId}`，计时中的时钟 / 气泡 `POST timer/place {taskId}`（请求里 `taskId` 与 `projectId` 恰好给一个）。落在「没挂任务」条上 = 记到项目。
  - 在面板任务列表的**空白处停住 1 秒** = 在那里长出一个新任务的名字输入；松手在输入上后输入名字回车，先建任务（`planner/tasks`）再把拖着的元素记进去；松手在别处 = 放弃，不建。已有的「分区空白处长按 / 停住亮满建项目」不变。

## 十三、Agent 页：一个 agent 一张卡（规范性，2026-11-12 追加，仓主定，nexus-core v2.54）

仓主：「人不需要单独的卡片，agent 页就是一张张 agent 工作的卡片，人的聚焦只是一小根红条在 agent 卡片内部的泳道上方，标尺对齐。一个 agent 一张卡」。

2. **时间范围 = 滚动窗口** `[此刻 − 范围, 此刻]`：日 = 24 小时，周 = 7 × 24 小时，拖动条 = 1–24 的整数小时，默认 3、打开时默认选中。拖动条拖动时只改旁边的数字，**松手**才重读重画。数据 `GET views/time-lanes?since=<窗口起点>`（v2.54）；打开时读一次、之后每 15 秒读一次。所有卡片的泳道共用同一把标尺，左右对齐；标尺刻度取整点（周取每天零点，写 `周X`）。

   - 卡片的底色与描边 = 这个 agent **现在**所属项目的颜色：卡里在跑的运行里最近开始的那条的 `projectId`；没有在跑的取最近开始的那条。
4. **人的聚焦 = 红条**：泳道上沿贴一条细红条（颜色 `--pr-human`），区间 = 卡里各运行 `attend` 的并集，与泳道同一把标尺。悬停显示 `HH:MM–HH:MM 聚焦`（窗口超过 24 小时前面加 `MM/DD `）。

6. **现在线**：一根红竖线贯穿所有卡片的泳道，在泳道右端（= 窗口终点 = 读到数据的此刻），线头标 `HH:MM`。
7. **飞入 / 飞回**：打开页面时，蜂巢上该 agent 的小人（同一卡里任一条运行的宠物，格子边的或左上角的）约 500 ms 飞到卡片名字左边的位置，原处的小人隐去；关闭（Esc / ✕ / 点空白）时飞回原处并恢复显示。卡里没有对应小人的（不在蜂巢上的）直接出现。`prefers-reduced-motion` 下直接到位。
8. **左上角头像**（`#stFish`）直径 72px：画「最常用的 agent」的 Q 版形象 = 最近 7 天干活时间最多的 `tool` 对应的宠物包（没有数据用缺省包 `deepseek`），取 `idle` 第一段视频停在第一帧（静态包用那张图），放大后只露头部。每 5 分钟重算一次。
9. 本版不做：点卡片放大的详情页、子代理闪现。

## 二十三、人的页面：拖卡时让开、泳道悬停提示 / 连线 / 置顶（规范性，2026-11-12 追加，仓主定，不改后端）

3. **连线**：悬停一段时，从该段下沿中点画一条线连到下面的卡，线画在一层盖住整个人的页面、不接指针的 SVG 上：
   - 「逐任务用时」里这一段所属的那张小卡：按该卡的归并键（任务 / 项目 / 手动计时 / 未分类）对应，同键没有卡时取同项目的第一张卡，仍没有则不连；

4. **窗口记录置顶**：悬停一段时，「窗口记录」把它对应的那个窗口块临时排到第一行（折叠时本来没露出来的也露出来，仍只显示前 5 行）；移开后恢复按用时从多到少的顺序。泳道本身不因此移动。
