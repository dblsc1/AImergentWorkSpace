## 一、布局（规范性）

宽屏（≥ 1280px）。手机端本版不做，以后用列表。

| 位置 | 放什么 | 数据 |
|---|---|---|
| 中间 | 蜂巢：每个项目一个格子，按分区分组。**格子上只有项目名** | 任务树 |
| 蜂巢正中心 | 聚焦代理的计时环（代理名 + 本次已用时间） | 「二」1 |
| 右上角 | 人的时钟：今天已记时长 + 当前项目名；一个气泡停在人所在项目的格子旁 | 「二」2 |
| 格子边 | 干活的宠物，至多 4 只 | 「二」3 |
| 左上角 | 没有去向的代理宠物，慢慢踱步 | 「二」4 |
| 左下角 | 「未分类」桶：`未分类 · 今天 X 小时 Y 分` | 「二」5 |

- 计时页（`/timer`）并入蜂巢页；旧地址跳转到蜂巢页。
- 决策栏照旧在页面上（只剩 AI 提议，见 `onboarding.v1`「八」）。

## 二、各部分的规则（规范性）

1. **中心计时环**：取 v2.17 `attend` 里人此刻在看的那条运行；人没在看任何代理 → 今天最后看过的那条；今天没看过 → 空环。
   人换着看别的代理时，环换成那条运行，过渡 ≤ 600ms。
2. **右上角时钟**：今天人的记录时长合计（手动计时 + 自动入账）。v2.16 `focus` 认出项目时，气泡停在该项目格子旁；
   项目变了，气泡沿弧线飞到新格子（约 600ms）；`focus.state: "afk"` 或认不出时，气泡回到时钟上。
   **手动计时**：把时钟拖到某个格子上 = 在该项目开始手动计时（离开电脑的事用它）；再点时钟 = 停。
3. **干活的宠物**：今天在跑、挂了任务或项目的运行，每条一只，停在它项目格子的边上，播 `working` / `waiting` / `idle` 动作（`desktop.pet.v1`「一」的 mood）。
   - 至多 4 只，按最近活动时间取；其余在蜂巢边显示一个 `+N`。
   - 用哪个宠物包：按运行的 `tool` 查「宠物包对照」（`desktop.pet.v1`「三」）；查不到用缺省包。
   - 只显示宠物与名牌（`label` 或 `agent`）；明细在点开格子后看。
4. **左上角：没有去向的代理**：今天在跑、`taskId` 与 `projectId` 都没有的运行，每条一只，在左上角区域慢慢随机走动。
   拖一只进格子 = `POST agents/{runId}/place {projectId, remember: true}`（「三」）；成功后宠物飞到该格子边，提示「已记下：以后 <agent> 都算 <项目名>」，3 秒后消失。
   放到空白处 = 回原位，什么都不改。
5. **左下角桶**：今天「未分类」窗口时间合计。点桶展开抽屉：`legible` 的块按秒数排，可拖；看不懂的按「浏览器（其他网站）」「终端（未认出）」「其他」合成灰色行，不能拖。
   拖块进格子 = `POST activity/blocks/assign {date, blockKey, ifSeq, projectId, remember: true}`；成功后块从抽屉消失、桶上时长减少，提示「已记下：以后 <displayName> 都算 <项目名>」。
6. **拖动**：原生 Pointer Events，鼠标、触控板都能拖。拖动中目标格子高亮；失败（`409` / `422` / 网络）时被拖物回原位并提示原因。

## 三、代理去向（规范性，nexus-core v2.44）

`POST /api/core/agents/{runId}/place`（只许人；带 Bearer 的设备令牌 `403`）

```jsonc
{ "taskId": "t_…" | "projectId": "p_…",   // 恰好一个
  "remember": true }                        // 缺省 true：同时写（或替换）一条代理去向规则
// 200 → { "runId": "run_…", "taskId": null, "projectId": "p_…", "rule": { "agent": "garden", "projectId": "p_…" } | null }
```

- 整条运行（从开始算）改挂到这个目标；读投影（`views/lanes`、`views/agent-time`、按天统计）按新目标重算这一条。运行不存在 `404`；目标不存在 `404`。
- **代理去向规则** `agent_place_rules {user, agent, taskId?, projectId?, createdAt}`，`(user, agent)` 唯一，至多 500 条（超了 `422`，什么都不改）。
  以后 `agents/start` **没给** `taskId` / `projectId` 时，服务端按 `agent` 完全相同查这张表，查到就挂上。给了的照旧以给的为准。
- `GET /api/core/agents/place-rules`（人与 MCP）列出；`DELETE /api/core/agents/place-rules/{agent}`（只许人）删一条，已挂上的运行不动。
- 进导出 / 恢复。

## 四、完成记录（规范性）

点格子弹出该项目的「完成记录」面板，可关。

- **左半边：人的时间**，两类，各一条时间线 + 合计：
  - 计时：手动计时与自动入账（v2.38 对账）落在该项目及其任务上的时段；
  - 对话：人看着该项目下代理的时段（v2.17 `attend`）。
- **右半边：代理的时间**：该项目下每条运行一行：名字、`working` 秒数、当前状态；底部一格「token 花费」，本版显示「—」。
- 数据来自既有读端（`views/lanes`、`views/agent-time`、`activity/ledger`）；本版不新增读端。

### 四·1 预留：代理用量（本版只定形状，不实现）

仓主 2026-11-07：「只留接口，包括 http 和 mcp 接口，先不做」。实现时按下面的形状，不另起名字：

- HTTP：`POST /api/core/agents/{runId}/usage {at, inputTokens, outputTokens, cacheTokens?, costMicros?, currency?}`（设备令牌 `report` 范围即可）。
- MCP：工具 `report_agent_usage`，参数同上加 `runId`。
- 事件：yq-event/v1 新增类型 `agent.usage`，`data` 同上（信封不变）。
- 读：「完成记录」右半边那一格读该项目下各运行的合计。

## 五、本版不做（有意的）

- 手机端（以后用列表）。
- 宠物之间的互动、宠物在格子间自由走动。
- 代理去向规则的前缀匹配（只认完全相同的 `agent`）。
