# `timer-ring/v1` —— 计时圆环视觉规范

**跨模块标准。一份规范，多个实现，不共享代码。**

与 `yq-event/v1` 同一个形状：`code/ring` 是它的**第一个实现者**，
但**实现与本规范不一致时，改的是实现，不是规范**。

## 为什么是规范而不是共享组件（人类裁决 2026-09-07）

人类的要求是「**圆环全站一个样**」，同时明确「**不用做进静态件**」（不注入共享 JS）。

这两条不矛盾：**统一靠写下来的规范 + 共享的设计变量，不靠共享代码。**

不做成注入件的三个理由（CFO 裁决，已被人类确认）：

1. **角色不同**：`navbar.js` 那个是「我在不在计时」的状态条（虚线小圈 + 文字走秒）；
   圆环仪表是布局元素，尺寸与位置由各页自己的布局算出来。
   塞进注入件 = 让页面布局依赖 nginx 模块的静态件。
2. **发布节奏不同**：注入件归 `nginx-docker`。调一次圆环样式要跨仓、走另一个 arbiter。
3. **轮询周期不同**：顶栏 10s 拉一次够用（`POLL_MS = 10000`），
   布局里的圆环要更勤。

**通用性已经由后端单例保证**——`timer_state` 是单例，任何页面拉 `views/current`
看到的都是同一段计时。ring 里点开始，table 刷新就在走秒。
**跨页一致不需要靠共享代码来实现**，那是后端的事。

## 几何（规范性）

| 项 | 值 | 说明 |
|---|---|---|
| `viewBox` | `0 0 200 200` | 圆心 `(100,100)`。整体尺寸由 CSS 控制，不改 viewBox |
| 刻度圈半径 | `r = 92` | 最外层，`class="ticks"` |
| 进度弧半径 | `r = 86` | 倒计时/单段进度用 |
| 贡献环半径 | `r = 78` | 「今日贡献」三段式用 |
| 描边宽度 | `stroke-width: 12` | 所有弧统一 |
| 端点 | `stroke-linecap: butt` | **不是 round**。相邻段之间不留圆头缝隙 |

两个半径**刻意分开**（86 / 78）：进度弧与贡献环各画各的，
互不遮挡也互不换算 —— 别为了"省一层"把它们合并。

## `pathLength="100"` 约定（规范性，本规范最值得抄的一条）

在 `<circle>` 上设 `pathLength="100"`，之后 `stroke-dasharray` 的单位**直接就是百分数**：

```js
el.setAttribute("stroke-dasharray", `${lengthPercent} ${100 - lengthPercent}`);
```

**不要再算周长**（`2πr`）。ring 的旧版有过一个 `circumference` 换算路径，已整段退役——
换算一多，半径一改就得同步改换算常数，迟早不同步。

新实现**必须**用 `pathLength="100"`。这是本规范的硬要求，不是建议。

## 颜色（规范性 —— 只准用设计变量，不许写死色值）

| 用途 | 变量 |
|---|---|
| 轨道底色 | `--panel-2` |
| 刻度 | `--line` |
| 主段 / 当前 | `--fact-s1` |
| 次段 | `--fact-s2` |
| 三段 | `--fact-s3` |
| 运行指示点 | `--fact` |

`tokens.css` 由 nginx 注入每一页，**这些变量在四个前端里都拿得到**。
深浅主题的适配由 tokens 负责，实现方不必也不该自己判主题。

`--fact-s3` 是**装饰档**：任务够多才有意义，只有两三个任务时别硬凑三段。

## 动效（规范性）

| 项 | 值 |
|---|---|
| 弧长变化 | `transition: stroke-dasharray 350ms ease-out` |
| 运行指示点 | `animation: ring-pulse 1.6s ease-in-out infinite`，`50% { opacity: .35 }` |
| 走秒刷新 | 每秒一次 |

**必须响应 `prefers-reduced-motion`**：设了就去掉 transition 与 pulse，直接到终态。

## 数据来源（规范性）

圆环**只读** `views/current`（或网关的 `/__cockpit/current`），
**不自己算跨页状态、不存 localStorage 当事实源**。

- `running` / `task.name` / `sessionStartAt` —— 当前段
- 走秒 = `Date.now() - Date.parse(sessionStartAt)`，**用单调差值，别累加本地计数器**

**空闲态 = 一个空圆环**（只有轨道与刻度，无进度弧）。这一条不变。

## 交互（规范性 —— 2026-09-07 人类改判，取代同日早些时候的「空闲态不可点」）

早些时候的口径是「空闲态本轮不做任何交互，不可点」。同日人类改判：

> 中间的计时圆环还不能打开，也做成鼠标放上去和点击的两档（点击直接进入到圆环界面吧）

所以**布局里的圆环仪表一律可点，包括空闲态** —— 空闲态点进去正是要去开始计时，
把它做成死的反而是把最顺的那条路堵上了。规范照改，不是只改实现（本规范第 6 行）。

| 档 | 行为 |
|---|---|
| 静置 | 圆环 + 当前任务名 / 「空闲」 |
| 悬停 | 容器稍微放大，多显示一行去处提示；圆环让出空间别把提示挤到边界上 |
| 点击 | **直接跳计时台**（`/ring/`），不在原地展开 |
| 按钮（2026-09-12） | 计时中 / 暂停中，悬停档露出 **完成 · 暂停 · 取消不记录**（暂停中是 **完成 · 继续 · 取消不记录**）；点按钮不跳页 |

可点就要能被键盘用：`role="link"` + `tabindex="0"` + Enter/Space，
`aria-label` 要说清当前状态（在计时 / 空闲）和点下去会发生什么。

## 蜂巢中心格变体（2026-09-12 人类改表盘）

> 计时数字放在圆环中心，少于 1 小时的时候显示分钟和秒，多于 1 小时显示时和分。白色短指针浮动在
> 内环作为秒针。全圆环浅青色但是再浅一点，深青色作为分针显示。作出一个记满一小时圆环青色走满一圈的效果。

中心格只有 50–67px 大，承担的是「现在在计什么、计了多久」一件事，所以它是本规范的**变体**：
几何（viewBox / r=92 刻度 / r=86 弧 / stroke 12 / butt / pathLength=100）照旧，改的是这几条：

| 项 | 中心格变体 | 说明 |
|---|---|---|
| 底色 | 计时中 / 暂停中 = 任务所在分区色**最深档再加一档** `color-mix(分区色 52%, --panel)` | 格子深浅 44%→20% 三档、一档 8 个百分点，中心格比紧挨它的格子深一档；空闲 = `--panel` |
| 轨道 | `color-mix(--fact 30%, 中心格底色)` | 整圈浅青，混进中心格自己的底色（取代 `--panel-2`） |
| 分针弧（r=86） | `--fact` | 60 分钟走满一圈；**跨整点时先走满整圈、发光 1.6s，再瞬间回 0**（不许带过渡倒转） |
| 秒针 | `--ink`，r 60–74 的一小截，圆头 | 累计角度（秒×6°）不取模，否则 59→0 会倒转一圈 |
| 圆心读数 | `<1h` 显示 `分:秒`，`≥1h` 显示 `时:分`；中心格**不显示单位小字**。悬停档读数偏上，下方一行简要标题，再下方开始时间（粗）+ 右下灰色小字「开始」，不显示日期 | 字号用容器查询单位，跟圆环等比；悬停档圆环到上方 30° 斜边的净距 = 到按钮上沿的净距（人眼比的是圆环到最近那条边）；数字按位记分牌翻牌，只翻变了的那位（人类 2026-09-12） |
| 贡献环（r=78） | **不画** | 那一圈让给秒针；ring 页主仪表照旧用它 |
| 运行指示点 | 不画 | 由秒针承担"在走"的信号 |

读数与分针都按「暂停前累计 + 本段」算（`nexus.timer.carry.v1`，见下节），只影响显示。

**长按接住时的闪烁**（人类 2026-09-12 四改后定稿：「闪烁颜色也需要是对应的分区色去闪烁的，闪烁完就是
对应的分区最浓颜色再加一档」）：中心格进悬停态 3 秒，底色在**中心格底色 ↔ 分区色本身**
（`color-mix(分区色 86%, --panel)`）之间闪 1.5 次，第 3 秒起从峰值渐变回中心格底色 —— 收尾关键帧与常态底色是
**同一个变量**，最后一帧分毫不差。全程不出现计划紫；飞进来的替身也一路保持源格子的分区色。
任务没有分区时退回：峰值计划紫、收尾 `--panel`。

## 计时控制按钮 + 暂停（纯前端）—— 2026-09-12 人类裁决

> 加入三个按钮……下半两个一个是完成一个是暂停。最底部是取消不记录。同样的，给计时面板也加上。
> 新增一个本次任务暂停按钮（纯前端活）。显示在中心计时圆环和计时面板中。后端接口保持不变。

**后端没有"暂停"，也不加。** 三个按钮全部落在既有接口上：

| 按钮 | 请求 | 语义 |
|---|---|---|
| 完成 | `POST /timer/stop` | 与「停止并记录」同一条，这一段入账 |
| 暂停 | `POST /timer/stop` + 写本机暂停记忆 | 这一段按真实起止入账；记住任务，等「继续」 |
| 继续 | `POST /timer/start {taskId}` | 对同一个任务**新开一段**；成功后清掉暂停记忆、写累计记忆 |
| 取消不记录（计时中） | `POST /timer/cancel` | 丢掉**当前这一段**，不产生事件；之前已入账的段不动 |
| 取消不记录（暂停中） | 不发请求 | 暂停时没有当前段 —— 只放下"还要继续"；界面必须说明"暂停前的时间已入账、撤不回" |
| 完成（暂停中） | 不发请求 | 暂停前的每一段早已入账，只清记忆 |

人类裁决（2026-09-12，三选一问答）：**暂停即入账，取消只作废当前段。**
备选的「暂停先 cancel、完成时再补登」被否：补登的事件 source 是 `manual-backfill`（"回忆填的"
证据强度），把表测的时间标成回忆，而且暂停期间的时间只活在一台浏览器里。

⚠️ **暂停不许只停前端走秒。** 后端一段计时 = start 到 stop；前端停表而后端不停，
暂停的那段照样被记成干活，之后没有任何接口能扣掉。暂停必须真的 stop，
两段之间的空白不属于任何一段，自然不记账 —— 任务总时长 = 各段之和，照样准。

**暂停记忆（跨模块共享，同源 localStorage）**：

- 键：`nexus.timer.paused.v1`
- 值：`{"taskId": str, "taskName": str, "projectName": str, "pausedAt": ISO8601}`
- 值里带 `carriedSeconds: int`：暂停那一刻"之前累计 + 这一段"的秒数（显示用）；
  可选 `startedAt: ISO8601`：这件事**最初**的开始时刻；可选 `zoneId`：暂停中中心格仍用这个分区的底色
- 只在 **stop 成功之后**写；`start` 成功、或发现 `views/current` 正在计同一个 `taskId`
  （在别处继续了）时清掉；暂停态点「完成」「取消」= 只清记忆，不发请求

**累计记忆**（「暂停后继续需要继续之前时间」，同源 localStorage，两模块同键）：

- 键：`nexus.timer.carry.v1`，值：`{"taskId": str, "carriedSeconds": int, "startedAt"?: ISO8601}`
- 「继续」成功后由暂停记忆的 `carriedSeconds` 转写；计时中显示的走秒 = `carriedSeconds + 本段`
- `views/current` 在计别的任务、或停下且没在暂停 → 清掉
- **只影响显示**：入账的仍是一段一段真实起止，任何一秒都不会被重复记
- 读写包 try：拿不到 localStorage 就当没暂停过，其余按钮照常
- 形状要改就升 `.v2`，别在 v1 上加必填字段 —— 两个模块不同时发布

确认：蜂巢中心格的「完成」「取消不记录」点两下（按钮原地变「再点确认」，3 秒复原）；
计时台的「停止并记录」**不要**二次确认（人类 2026-09-12），「取消，不记录」维持原有弹层。

## 不在本规范内的

- `navbar.js` 的顶栏状态条（虚线小圈 `r=8` + 文字走秒）——那是**状态指示**，不是圆环仪表，
  两者刻意不同构。别把它往这份规范上靠
- 圆环外层的容器尺寸、留白、与周围元素的关系 —— 各页自己定
