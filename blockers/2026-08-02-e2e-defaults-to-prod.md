# 障签 · E2E 测试默认打生产栈

- 立障：2026-08-02
- 立障方：CFO（核实 E2E 交付时发现）
- 判定：**不阻塞**（测试目前不自动跑，要人手工触发）
- 波及：（不设）

## 现象

`code/{ring,table}/review/reviewcode/tests/conftest.py`：

```python
GATEWAY_BASE_URL = os.environ.get("COCKPIT_TEST_BASE_URL", "http://127.0.0.1:8081")
```

**默认值指向生产栈**（真实的 nexus_core 库）。

## 已经造成的实际后果

reviewer 在开发这套测试时撞到两次，都如实报告了：

1. 复现 `findTaskById` 缺 `projectId` 那个 bug 时，坏掉的 `<select>` 回退到第一个
   选项，于是**真的把测试任务挂到了用户真实的「英语学习」项目下**。
2. 一次等待逻辑超时发生在实体已在服务端创建、但 ID 还没记下之前，
   **遗留了一个孤儿分区** `E2E-chain-...`，事后人工找出来删掉的。

两次都被发现并清理了，环境已核实回到基线。**但两次都是靠人眼兜住的。**

## 为什么这是设计问题不是"测试没写好"

**同一形状今天第二次**：

| | 默认值指向 | 后果 |
|---|---|---|
| `conftest.py`（单测） | 生产库 | 我传了真库名，62 个测试清了 62 遍，**用户计时历史全丢** |
| `conftest.py`（E2E） | 生产栈 | 测试往真实数据里写东西 |

第一个我今天修了（硬拒绝非 `_test` 库名），**却没扫同类**——铁律 23 要求的
「这个形状还出现在哪」我当时没问。E2E 这份就在隔壁，同一个文件名，同一个坑。

## 处置方案（已定，等 nexus-core 那边的 agent 完工后做）

不能只把默认值删掉——人会直接填 8081。要的是**机械判据**：

1. **`GET /api/core/health` 返回当前库名**（契约变更）。
   它在 `auth_request` 之后，只有登录用户看得到，可接受。
2. **E2E 启动时查一次，库名不以 `_test` 结尾就 die**——
   与 `conftest.py` 单测那道护栏**同一个判据形状**，不再各写各的。
3. 提供 `stack-up-test.sh` 起隔离测试栈（测试库 + 独立端口）。

（即那份 conftest 里出现库名护栏。现在没有，修好后才会有。）
