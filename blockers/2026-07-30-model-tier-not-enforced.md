## 现象

`agents/protocol/orchestration.md` 第 6 条（用户 2026-07-30 裁定）写明：

> reviewer 与 arbiter 的**常规轮次（无打回）一律用中档模型（sonnet），不用高档（opus）**。
> 升档只在：打回后的复审、跨模块/架构级裁决分析。
> **省下的不是钱是延迟——常规审查用高档是浪费，不是审慎。**

**我一次都没照做。** 实证：

| 派出的活 | 应用档 | 实际 | 消耗 |
|---|---|---|---|
| cfo_reviewer 第 1 轮（初审，无打回） | 中档 | **继承高档** | 11.2 万 token |
| cfo_reviewer 第 2 轮（打回复审） | 高档 ✓ | 高档 | 19.2 万 |
| cfo_reviewer 第 3 轮（打回复审） | 高档 ✓ | 高档 | 22.6 万 |
| programmer 各轮 | 执行档 | CLI 默认 | —— |

三轮 55 万 token，**其中第 1 轮本该走中档**。用户直接问「你开的 subagent 都是什么 model？
usage limit 走得飞快」时我才去查。

## 为什么会漏

**两处都没有传模型的地方**：

1. **子代理机制**：开的时候不指定模型就**继承派活方的档**。没有任何提示会说
   「你正在用高档开一个常规审查」。
2. **`scripts/run_agent.sh` 第 46 行**：
   ```
   args=(-p --agent "$role" --output-format json --permission-mode "$perm")
   ```
   **没有 `--model` 参数**，也没有对应的环境变量入口（对比：权限档有
   `AIMERGENT_AGENT_PERMISSION_MODE`）。

所以这条规矩**只能靠派活方每次记得**。而按本仓已立的判例——
**凡是「下次记得」都该读成「尚未修复」**。

## 解除标志

`run_agent.sh` 支持模型档之后会出现该环境变量名：

解除标志：`AIMERGENT_AGENT_MODEL` @ `scripts/run_agent.sh`

## 归属与修法

框架侧（`scripts/` 归 consulter）。CFO 不代改。

建议：
1. `run_agent.sh` 加 `AIMERGENT_AGENT_MODEL`（默认中档），与权限档同形
2. **默认中档而非继承** —— 让「省」成为默认、「升档」成为需要显式写理由的动作，
   方向与现在正好相反
3. 若能在 diary 的 `run_agent` 事件里记下实际档位，"高档占比"才成为可看的数字
   （现在 `perm` 记了、`model` 没记）
