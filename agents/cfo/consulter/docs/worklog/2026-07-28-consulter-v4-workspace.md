# V4 工作空间升级

## 做了什么

按人类 2026-07-28 的九条裁决，把框架从 V3 升到 V4：

1. **顶层重组为 4 目录 + 3 根文件**（从 11 项降下来）。只搬位置不改内容；
   全仓路径引用同步重写；白名单 `.gitignore` 补放行项。
2. **公式化操作全部脚本化**：`dispatch.sh`（派活，含角色卡首行与开卷判据）、
   `exam.sh`（开工考试，只考通用流程）、`mission_complete.sh`（完工硬闸门）、
   `reindex.sh`（留痕索引）、`console.sh` + `logs/console.html`（控制台原型）。
3. **检查项做成可增删改查**：`scripts/checks/` 六个独立文件，主脚本只是遍历执行器。
4. **修 12 条已知缺陷**，含我 V3 引入的回归（新模块首跑门禁必红）。
5. **`selftest.sh` 扩到 12 条断言**，框架仓自己 12/12 全绿（V3 时是 1 绿 4 红）。

## 为什么这么做

**核心判断：能被脚本执行的规矩才是真规矩，只能被阅读的规矩都是成本。**

本轮实证：`time_management` 全仓 101 个文件、业务代码 0 行；而它违反的每一条规范
都是白纸黑字写着的。规范不缺，缺的是执行者——20 条铁律里只有 5 条有机械执行者，
写得最死的铁律 1（分支纪律）执行者是「无」，于是 10 个 commit 全直提 main 无人察觉。

所以 V4 的重点不在写更多规范，在把已有规范接上执行者。

## 关键决定与代价

- **留痕保持分散 + 生成索引**（人类裁决）：解决「找不到」，不解决「读不完」。
- **规范只删重复**（人类裁决）：篇幅降约 20%，结构与条款不动。
- **硬闸门必须有逃生口**：`AIMERGENT_MISSION_OVERRIDE` 放行但强制记账。
  没有逃生口的硬闸门，第一次误判就会让人把整个 hook 删掉——那比软提醒更糟。
- **exam 只考通用流程**：题库一旦沾项目内容，每建一个模块都要维护一套题，必然腐烂。
  任务特定要求由 arbiter 写进任务单、由 `scripts/checks/` 机器核验。

## 冒烟抓出的三处（2026-07-28 补记）

空仓 clone 冒烟一次抓出三个真 bug，都是重组的连带伤：

1. `new_module.sh` 的 `TEMPLATE` 默认值仍指 `module_template` —— 我的路径替换只覆盖了
   带斜杠的写法，不带斜杠的漏网。
2. `install-ci.sh` 仍把门禁装进模块的 `ci/`，而 `run-gates.sh` 内部已改引 `scripts/`，
   两边对不上 → 新模块门禁根本跑不起来。
3. `dispatch.sh` 在模块内解析不到框架根。改为 **env 优先 + `.aimergent-framework` 回退**，
   不硬编码绝对路径（正是 copycat 那条 `@/srv/aimergent/0/...` 的病）。

**教训**：字符串替换类重组，必须靠一次真实的空仓走查兜底——静态 grep 看不出「两边对不上」。
这也是验收清单第 8 条（框架自身走得通）存在的理由。

## 门禁两次当场拦住我自己

- 第一次拦 `60-doc-paths-exist`：它把「按任务产出、此刻尚不存在的 report.json」判成了错。
  据此把判据从「文件必须存在」改成 **「文件所在目录必须存在」**——目录不存在才是真问题
  （agent 不会往不存在的地方写），文件没产出是正常状态。
- 第二次拦 `10-worklog-changed`：我提交冒烟修复时没写 worklog。规矩对我一样生效。

## 「新模块门禁必红」的正确解读（补记）

冒烟最后一步：新脚手模块跑 reviewcode 会红在「module_docs 仍有语义占位符」。
**这是对的行为，但表达错了**——它是待办清单，不是故障。已改成点名具体文件，
脚手输出也明确写成「先填 module_docs，此前会红，那是待办不是故障」。

区分「未完成」和「坏了」很重要：把待办报成故障，人第一反应是去查工具，
而不是去干那件该干的事。
