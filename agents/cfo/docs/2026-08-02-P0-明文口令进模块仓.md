# P0 · 开发口令明文进了模块仓（铁律 2）

**发现人**：gantt 的 programmer_reviewer，在做 E2E 时需要口令，**从别人的留痕里读到的**。
**记录人**：CFO　**日期**：2026-08-02

---

## 一句话

四个模块的 worklog / reviewreport / handoff / report.json 把开发口令原样贴了进去，
**而那些文件正是在论证「口令没有进测试文件」**。

---

## 泄露面（机械核过，不是估计）

| 仓 | 可见性 | 当前树 | 历史 |
|---|---|---|---|
| `cockpit-ring` | PRIVATE | 4 个文件 | 2 个 commit |
| `cockpit-table` | PRIVATE | 5 个文件 | 2 个 commit |
| `cockpit-gantt` | PRIVATE | 2 个文件 | 2 个 commit |
| `cockpit-nexus-core` / `-auth` / `-nginx-docker` | PRIVATE | 0 | 0 |
| **`AImergentWorkSpace`（框架根）** | **PUBLIC** | **0** | **0** |

核验命令（两条都跑过，公开仓两条都空）：

```bash
git grep -n "<口令>" HEAD --          # 当前树
git log --all --oneline -S"<口令>"    # 全部历史
```

**公开仓干净**，当前树和全部历史都没有。泄露只在五个 private 仓里的三个。
这把等级从「公网泄露」降到「私仓明文凭据」——仍是铁律 2 违规，但不是紧急事故。

---

## 为什么会这样：判据只盯了写代码的人，没盯写判据的人

reviewer 的报告里逐字写着：

> `grep -rn <口令> review/reviewcode/tests/` 零命中

**这句话是真的**，测试文件确实干净。然后紧接着的下一行是：

> `$ export COCKPIT_TEST_PASSWORD=<真值>`

判据盯的是 `tests/` 目录。**证明合规的那份文档本身不在判据范围内。**
这是本轮反复出现的同一形状：判据覆盖了一半，另一半恰好是它自己。

---

## 止血（已做）

1. **公开仓已核干净**——最坏的那种情况没有发生，这是本条不升级为紧急的唯一理由。
2. **判据草稿已写并正反验过**：认「`*_PASSWORD|TOKEN|SECRET|APIKEY` 赋值且右侧是字面量」，
   放行 `$VAR` / `${VAR}` / `os.environ` / `getenv` / 占位符 / 纯散文提及。
   **判据里不含任何真实口令**——把口令写进判据本身，等于为了防泄露而泄露。
   落点归 consulter（`scripts/` 是它的写区，CFO 不越界写）。
