# 任务单 · `60-doc-paths-exist.sh` 惩罚准确留痕（框架）

- 派活方：cfo · 日期：2026-08-11 · tier：normal · 档位：Sonnet

## 目标

修 `scripts/checks/_common/60-doc-paths-exist.sh` 的历史叙事排除模式漏掉
J3 之后的 canonical worklog 落点，导致**如实记录删除的 worklog 被判死链**。

## 问题（CFO 实测）

```bash
$ grep -n worklog scripts/checks/_common/60-doc-paths-exist.sh
13:  case "$f" in */docs/worklog/*|*/docs/findings/*|*/docs/decisions/*) continue ;; esac
```

排除模式要 `/docs/worklog/`，而**裁决 J3 之后 arbiter 的 worklog 落
`module_docs/worklog/`** —— `module_docs` ≠ `docs`，**匹配不上**。
programmer 侧的 `code/<子文件夹>/worklog/` 同样匹配不上。

**后果**：一条如实写「我删除了 `code/_template/module_docs/reviewlog.md`」的 worklog，
会被判成引用了不存在的路径。**这是在惩罚准确留痕** ——
它教下一个 agent 要么不写清自己删了什么，要么用 override 绕过。

实证：nexus-core 那轮 arbiter 就撞上了，只能用模块本地逃生口
（`scripts/gates/doc-path-exempt.local.txt`）绕过。**这会在每个 J3 之后的模块里复发。**

## 你要做的

1. 修排除模式，覆盖 canonical worklog 的**全部**落点。
   落点的唯一事实源是 `agents/protocol/report-schema.md` 的 canonical path 表——
   **去读它，别照我这份任务单猜**。
2. **铁律 23 修到类**：仓里还有哪些地方在用「`*/docs/xxx/*` 猜 canonical 落点」
   这种模式？同类一并修。
3. **留断言，正反两侧**：正例——J3 落点的 worklog 里写一条已删除路径，**不该报**；
   反例——**非**叙事类文档（如 `contract.md`、`handoff.md`）里写死链，**必须还能报出来**。
   只加正例＝可能把检查改瞎了。
