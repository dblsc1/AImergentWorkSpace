# 2026-08-03 · CFO · 开工考试在教错的报告落点

## 怎么发现的

推 ring 时门禁红在 `report schema: 缺少必填字段或 path/role 不匹配`。
查下去：报告本身字段齐全，**是落点错了** —— 放在 `codeagent/programmer_reviewer/docs/`，
而 `report-schema.md` 规定 reviewer 的 canonical path 是 `review/reviewreport/report.json`。

再查 table，**同样放错**。两个独立 agent 同一个错，那就不是它们的问题。

根因在 `scripts/exam.sh` 第 48 行：**开工考试的答案键自己硬编码了
`codeagent/$role/docs/report.json`**，那是 J3 迁移之前的旧布局。

**考试是每个 agent 干活前的第一课。** 它教错，等于批量生产错的产物 ——
而且 agent 越守规矩，错得越整齐。

> **教错的指引比没有指引更糟**：没有指引人会去查，教错了人会照做。

## 修到类，不是改那一行

把答案键从「自带一份路径表」改成「**从 `report-schema.md` 读**」。
schema 表每行末尾加一个 `<!-- role:<slug> -->` 机器锚点 ——
渲染时不可见，人看的表和机器读的是**同一行**，不可能再分叉。

查不到锚点时**响亮失败**，不猜一个路径出来 —— 猜正是本次要根治的病。

## 断言（铁律 23）

`selftest` #69：六个角色逐个比对「考试读到的」与「schema 写的」。反向三发：

- **A** 改回硬编码 → 红
- **B** 拆掉一个锚点 → 红，点名是哪个角色
- **C** 改 schema 里的路径 → **绿，这是对的** ——
  改 schema 是合法变更，考试跟着走，正是单一事实源的意义。
  一发「不该红的没红」和两发「该红的红了」同样是证据。

## 写断言时我自己又踩了同一个坑

第一版判据是 `grep 'codeagent/$role/docs/report.json' exam.sh`，
结果被 **exam.sh 里解释这件事的注释**绊倒 —— 那条注释里必然写着那个字面量。

**「讲某个字面量的文档会成为那个字面量的新实例」，今晚第四次。**
（前三次：consulter 的审核报告、我讲密钥判据的注释、密钥断言的 fixture。）
判据改成只看非注释行。

## 追加：第四条摩擦（比前三条严重）

table 的 reviewer 报出：**它的工作树里混进了我的暂存** ——
`scripts/exam.sh`、门禁同步任务单、一行推送记账。`05-write-lease` 当场拦红了它。

病根：**路签是按路径发的，而 `git add` 写的是整个仓共享的 index。**
两个写者只要在同一个工作树里，一方的暂存就会出现在另一方的提交面上。
**铁律 15「一分支一活跃写者」正在被破，而路签拦不住。**

我今晚在 gantt 和 nexus-core 两次用路径限定提交（`git commit -- <paths>`）躲过去 ——
**那是运气不是设计**：我知道有人在里面干活所以特意绕了，下一个人不会知道。

已写进给 consulter 的摩擦清单（第 ④ 条），收尾问句：
**看到任何「按路径隔离并发写」的机制，先问「它隔离的是路径，还是隔离了写这一动作本身？」**

我自己的做法即刻改：**agent 干活期间不动同一个模块的工作树。**
但今天反复证明靠纪律不管用，机制侧交 consulter。

## 顺带核实了一条别人报的残留风险

nexus-core 的 programmer 提醒：`backup.sh` 在备份仓没配远端时只打警告仍返回 0，
所以不能把它退 0 当成「备份已上远端」——那正是本项目实证过一次的假保险形状。

**我核了，不是假设**：`cockpit-archived` 的 origin 已配，本地 HEAD 与远端一致，
最新一份是 `daa7293`（删除操作前那次）。这台机器上这条风险不成立。
但它指出的判据缺陷是真的，该修 —— 已记。
