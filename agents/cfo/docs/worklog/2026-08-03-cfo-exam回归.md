# 2026-08-03 · CFO · 我修 exam.sh 时引进的回归

## 是模块里的 programmer 报上来的，不是我的断言抓的

上一轮我把考试的答案键改成从 `report-schema.md` 读。**同一轮我引进了两个新 bug：**

**① 调了一个全仓从未定义过的函数。** `_framework_root` 在 exam.sh 第 49 行被调用，
`grep -rn` 全仓零命中。模块是**独立 Git 仓**、仓内没有 `agents/protocol/`，
于是路径塌成 `/agents/protocol/report-schema.md`，**每个模块里的考试都必错**。

**为什么我的断言没抓到**：#69 只在**框架根**跑，第一个分支就命中，
**恰好是能工作的那一半**。

> 「判据只覆盖了粗心的那一半，没覆盖搞错的那一半」——
> **我在写完这条教训的下一轮，就自己犯了。**

**② 判据比的是模板占位符。** schema 表里写的是 `code/<子文件夹>/report.json`，
而考生答**正确的具体路径** `code/backend/report.json` 反而判错 ——
等于逼考生去背占位符而不是理解落点。

## 修法

`lib/paths.sh` 里本来就有 `framework_root()`（靠模块根的 `.aimergent-framework`
标记回溯），exam.sh 只是从没 source 过它。改成 source + 用它。

**找不到事实源时响亮死**，并且**说清是判卷器坏了不是考生答错了** ——
原来那条错误信息指向「先补机器锚点」，会把人引去改一个不相干的地方。
新文案里明写「请报告给项目 arbiter，**别改答案去迎合它**」。

模板形态与具体路径**都算对**。

## 断言补了模块场景，反向两发

- 拆掉回退 → 红：「在**模块仓**里考试找不到 report-schema」
- 拆掉 schema 锚点 → 红：「[cfo schema 里没有锚点]」

## 写这条断言时我又踩了一次「断言根本没在看」

第一版喂的是 `--submit /dev/null`，而 exam.sh 在「答案文件不存在」那步就退出，
**根本走不到判卷**。于是断言在看一段永远不会产生的输出，反向验证不变红。
改成喂真实文件才对。

**今晚第八次「我的验证方法错了」**，而这一次错的是**用来验证我修复的那个断言本身**。
