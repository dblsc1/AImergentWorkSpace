# 任务单 · JSON 一键导入编辑接口（planner CRUD）

- 派活方：cfo · 日期：2026-08-12 · tier：hard · 档位：Sonnet
- 需求：用户要「导出 JSON → 编辑器里改 → 导回去直接生效」的外部编辑通道

## 现状（CFO 已核）

- `GET /api/core/export` **已有**，返回 `{zones, projects, tasks, events, projections, exportedAt}`
- **导入端点不存在**，本单新建

## CFO 定的架构（复用已验证的形状，别另起一套）

**`POST /api/core/import`**，吃**与 export 同形状**的 JSON（改完导回去）：

1. **默认 dry-run**：只回 diff 计划（要建/改/删什么，逐条），**一个字节都不写**。
2. **执行要带计划校验和**：真执行时必须回传 dry-run 那份计划的 checksum，
   服务端比对不上就拒 —— **防止拿一份过时的计划去应用**（库在这期间可能已经变了）。
3. **`events` / `projections` 出现在 payload 里 → 400 拒**，并点名字段。
   **不许静默忽略** —— events 是 append-only 事实台账（宪法红线），
   静默忽略会让用户以为改了其实没改，比报错坏得多。
4. **删除要显式开关**（如 `allowDelete: true`）。缺省不删 —— 导出的 JSON 里少一个对象，
   最可能是用户手滑，不该当成"删掉它"。
5. `actor`：走人的路径，`actor=human`。与 v1.6 的来源设防口径一致。

**这就是 AI 那套「低风险直接做 / 高风险先提议后确认」的同一形状**，已被真 AI 压过一轮，复用它。
