## ring 指出的契约缺陷，我采纳并自己修了

`{"detail": ...}` 的 4xx 错误形状**从未写进契约**，只是 exception handler 的
观察行为。而 ring 与 table **都原样展示 `detail` 给用户**（这是我们有意定的
纪律：后端是权威，前端不重复校验）。

比它说的更严重：形状一改，**两个前端同时静默失败，且没有任何契约违反能被抓住**
——报错框变空白，而测试照样绿（断言的是状态码不是 body）。

已补进 nexus-core 契约 v0.7，三条约束 + 消费方登记。

**没写进契约的依赖，就是没人守的依赖。**
