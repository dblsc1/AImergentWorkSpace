# 任务单 · 补登（backfill）—— 契约 CR + 两前端入口

- 派活方：cfo · 日期：2026-08-19 · tier：hard（跨 3 个模块 + 改契约）
- 人类需求原话：「计时器和网页前端都加个功能，补登，用于完成了但没计时的情况。」

## 目标

给「完成了但没计时」的工作补一条真实记录。nexus-core 的 `timer.v1` 加一个
`POST /api/core/timer/backfill`，ring 与 table 各加一个入口。
**契约先行，零投影改动**——若实现中发现必须改投影，说明本设计有错，停下上报。

## 人类已定的三个口径（2026-08-19，不再讨论）

1. **表单粒度＝任务 + 日期 + 开始时刻 + 时长**（不是「日期＋时长」，也不是「起止两端」）
2. **入口＝ring + table 两处**（gantt 不加写入面，保持只读视图）
3. **必须挂具体任务**，不允许只挂项目

## 先说为什么这不违反「events 不准动」红线

红线有两层，都不挡这件事：

- 「AI 不准写 events」——补登是**人**在前端点的，`actor` 走人的路径，不是 ai-planner。
- 「只增不改不删」——补登是**追加一条历史事实**，正是 append-only 台账的设计用法。
  `contracts/yq-event-v1.md` §4（双时间）明写 `time` 可以是过去，
  `daily_stats.py` 的 docstring 里也已经点名「补交事件（B7：`time` 可以是过去）」。

**没有任何一行代码需要改 events 的写入约束。**

## 核心结论：零投影改动

实读代码确认（2026-08-19）：

| 投影 | 归属键 | 补登影响 |
|---|---|---|
| `proj_daily_stats` | `(user, date, projectId, taskId)`，`date` 取 **`data.startAt`** 经 `NEXUS_TZ` 归日 | 只要 `startAt` 给对，自动落对日子；跨零点归开始那天，与实时计时同一套逻辑 |
| `proj_current` | 全时段累计，**无日期维度**（`repo.apply_session` 只 `$inc`，不看时间） | 补登是真事实，计入累计正确 |

甘特事实图层只存「某天多少秒」，**没有任何界面显示时刻**。
所以开始时刻这个输入当前不影响任何渲染——它的价值是让档案里的
`startAt` 是**诚实值**而非编造值（人类选粒度 2 的理由），以及跨零点归日正确。

只要补登组出的信封 `data` 形状是 `{durationSeconds, startAt}`（与
`timer/service.py::stop` 完全一致），两个 handler 一个字都不用改。

## 契约 CR（nexus-core，`timer.v1` 加一个端点）

### 端点

`POST /api/core/timer/backfill`

请求 `TimerBackfillIn`：

```json
{
  "taskId": "t_a1b2c3",
  "startAt": "2026-08-18T14:30:00+08:00",
  "durationSeconds": 5400
}
```

响应 `TimerBackfillOut`：

```json
{
  "recorded": true,
  "duplicate": false,
  "date": "2026-08-18",
  "event": { "id": "evt_...", "dedupeKey": "backfill:...", "type": "session.completed" }
}
```

`date` 是**服务端算好的归日结果**回显给界面——让用户看见「这段记到了 8-18」，
而不是自己在前端再算一遍时区（两处算 = 迟早不一致）。
`duplicate: true` 表示防重命中，界面要说「这段已经补过了」，不能装作新记了一条。

### 服务端组装的信封（规范性）

| 字段 | 值 | 为什么 |
|---|---|---|
| `source` | **`"manual-backfill"`**，不是 `timer-backend` | ① 唯一约束是 `(user, source, dedupeKey)`，换 source 后补登键与实时计时键**结构上不可能撞**；② 档案必须能分辨「表测出来的」和「人回忆的」——这是两种证据强度，混成一个 source 就永远分不开了 |
| `dedupeKey` | `backfill:<taskId>:<startAt 归一化为 UTC ISO>:<durationSeconds>` | **内容派生的确定性键**。同一任务 + 同一开始时刻 + 同一时长重复提交 = 只落一条。双击、断网重试、用户以为没成功又点一次，全都幂等，且**不需要前端存任何状态**。归一化必做：`+08:00` 与 `Z` 两种写法指同一时刻，不归一就是同一件事两个键 = 防重失效 |
| `time` | `startAt + durationSeconds`（会话结束时刻） | 与 `stop()` 的 `"time": now` 语义对齐（对 `session.completed` 而言 `time` ＝ 结束那刻） |
| `subject` | zone/project/task **在服务端从 planner 硬取全链**，与 `start()` 同一套 | 断链当场响亮失败，不留给投影去静默跳过 |
| `data` | `{"durationSeconds": n, "startAt": "..."}` | **与 stop 完全同形**，这是零投影改动的前提 |
| `flags` | `[]` | 不新增 flag。`source` 已经是判别位，加 flag 是重复的契约面 |

### 拒绝规则（规范性，全部响亮报错，不许静默吞）

| 情形 | 状态码 | 理由 |
|---|---|---|
| `taskId` 不存在 / 归属链断裂 | 404 | 与 `timer/start` 同一判据，同一套报错文案 |
| `durationSeconds` 非正整数 | 400 | |
| `durationSeconds > 86400` | 400 | 单段会话不可能超过一天。这条主要拦**单位填错**（把 90 分钟填成 90 但后端当秒，或反过来），不拦也能落库，但会污染统计且极难发现 |
| `startAt` 不带时区偏移 | 400 | **不许猜**。缺偏移就猜 `NEXUS_TZ` 会在跨时区/夏令时上静默错日，且错得看不出来 |
| `startAt` 无法解析 | 400 | |
| `startAt + durationSeconds > now` | 400 | 不能补登未来 |
| 过旧的 `startAt` | **不拦** | 补三个月前的活是正当需求，没有理由设限 |

### 与活状态计时的关系（规范性）

**补登完全不碰 `timer_state`**：不 stop 当前计时、不被当前计时阻塞、正在计时时也允许补登。
理由：补登说的是「过去某段时间我干了活」，与「我现在正在干活」是两件独立的事。
让它们互相干扰会制造一个很烦的伪约束（想补登得先停表），而这个约束换不来任何正确性。

**允许墙钟重叠**，不做仲裁。补登天然是事后行为，无法也不该要求它与历史记录不重叠。
（这与「多计时器前台/后台仲裁」是两个议题，**不在本任务范围**。）

## 前端 CR

### 共享还是各写一份 —— CFO 裁决：**各写一份，不共享代码**

ring 和 table 是**两个独立模块仓**，各有 arbiter。抽一个共享 `backfill-dialog.js`
要新造一套跨仓分发机制，而铁律 8 明写「模块只经契约依赖」。
**耦合点就是这个 HTTP 端点，这是设计，不是妥协。**
代价是一个对话框写两遍，接受。

### ring（`code/ring`）

入口：空闲态在「计时方式」两个 tab 旁边加「补登」。运行态**也要能点**（二者独立，见上）。
复用现有 `postCore`。任务下拉复用现有取任务列表的路径。

### table（`code/table`）

入口：任务行上加「补登」按钮，点开时任务字段**预填该行任务**且不可改
（从任务清单进来的人已经指定了任务，再给个下拉是多余的一步）。

### 两端共同要求

- `duplicate: true` 必须显示成「这段已经补过了」，**不许显示成「已记录」**——那是骗用户
- 提交失败要显示服务端的具体报错文案，不许吞成「失败了」
- 提交成功回显服务端返回的 `date`，不在前端算时区

## 测试（铁律 17，新增代码必须同批新增测试）

**nexus-core programmer（pytest）**：
- 防重幂等：同一 `(task, startAt, duration)` 提交两次，`events` 只多一条，`proj_current` 只加一次
- 归一化：`+08:00` 与等价的 `Z` 写法产出**同一个** dedupeKey
- 跨零点：`startAt` 为本地 23:40、时长 40 分 → `date` 归到**开始那天**
- 上表 7 条拒绝规则逐条
- 补登**不改** `timer_state`：正在计时时补登，`views/current.running` 保持不变

**nexus-core reviewer（整合级，落 `review/reviewcode/tests/`）**：
- 补登 → `GET /api/core/views/gantt` 对应日期的 `actual` 秒数增加
- 补登 → `GET /api/core/export` 的 `events` 里出现该条且 `source == "manual-backfill"`

**ring / table**：各自 Playwright，含 `duplicate` 分支的显示。
