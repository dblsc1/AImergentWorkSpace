## consulter 判 rejected，判得对

v1 实测 14 种形状**只拦住 2 种**。更要紧的是它指出：那两条 `grep -v` 过滤器是**行级**的，

## 我的立项诊断错了一条，这条比判据本身重要

我说 `.gitleaks.toml` 是「空壳零规则」。**不是。** 它是 `[extend] useDefault = true`，
继承 gitleaks 上游一百多条默认规则，**而且 CI 里一直在跑**（`ci.yml` 的 gitleaks-action）。

真实缺口只有本地两条：本机没装二进制 + `RUN_GITLEAKS_LOCAL` 默认 0。

**代价具体**：按「空壳」这个诊断，下一步是往我的判据里塞更多正则；
按真实诊断，下一步是**本地把 gitleaks 装上** —— 而 v1 漏掉的 AWS 密钥 / GitHub PAT /
PEM 私钥**恰好全在 gitleaks 默认规则里**。

**修对了不等于诊断对了。诊断错会把下一步引偏。**

本判据 v2 因此重新定位：**只补 gitleaks 天然抓不到的那类** —— 项目自定义的、
无固定指纹的弱口令（词+年份那种，任何基于熵或指纹的规则都会放过）。

## v2 形状

判断对象是**右值**不是整行。键名大小写不敏感、认词边界；右值只有**整体**
像占位符 / 是变量引用 / 是读 env 的调用才放行。

## 三类真实误报，靠全仓实跑逼出来（单元样本一个都没暴露）

| 误报 | 病根 | 修法 |
|---|---|---|
| `CL_PASS=0`（计数器） | 键名正则认裸 `pass` | 改成必须 `pass(word\|wd)` |
| `if (e.pass === false)` | `=` 匹配到了 `===` 的第一个 | `=(?!=)` |
| `..._TOKEN_FILE="$token" \` | 续行反斜杠破坏引号剥离 | 剥引号前先去尾部 `\` `,` `;` |
| `18-secret-literal.sh:36` | 文件名含 secret + `:行号` 被读成赋值 | 键名像路径就跳过 |
| 注释里讨论这件事 | 右值是散文 | **真凭据不含空白**，带空白一律放行 |

最后一条是最省事也最普适的一刀。

## 追加：判据拦下了自己的断言 fixture

`selftest` #61 的十条坏样本原本用 heredoc 写在分片里 —— **本判据扫暂存文件，
于是断言的 fixture 自己被拦下，提交不了。**

consulter 的 `ref-fixture` 行级标记在这里**用不了**：标记会随 heredoc 一起写进
沙箱的 `bad.txt`，让沙箱里跑的判据也跳过它们，**等于把断言本身关掉**。

改用本仓既有的**拆分书写**惯例（同 selftest #17 对模板占位符的做法）：
键名拆两段拼接，源文件里永远不出现完整的 `KEY=VALUE` 形态。
**没有另造第二套豁免机制。**

这是同一个形状在本轮的第三次出现：
① consulter 的审核报告成了它审的那个缺陷的新实例
② 我讲判据的注释被判据自己拦下
③ 断言的 fixture 被断言要测的判据拦下

**通则：任何「检测某种字面量」的判据，它自己的文档与测试样本都会成为它的输入。**
写这类判据时，第一件该问的是「我的样本放哪儿才不会被我自己吃掉」。
