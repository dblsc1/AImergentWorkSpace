### A-1. 所有逃生口的记账账本，全都不进 Git（CFO 今天亲手造成）

**问题**：框架的逃生口（`AIMERGENT_MISSION_OVERRIDE`、`AIMERGENT_PUSH_SKIP_GATES`）
都宣称"放行但记账，绝不静默"。记账写进 `logs/diary.jsonl`。
**但五个仓的 `logs/diary.jsonl` 全部不被 Git 跟踪。**

按铁律18 自己的判据——"未被 Git 跟踪、落在仓外/临时目录的一律按「未产出」处理"——
**今天全部 15 次逃生口使用，等于没记账。** 换台机器、清个工作区，全部蒸发。

**这是我今天亲手做的**：早些时候 `logs/` 被 Git 跟踪导致门禁红（`console.json` 里有
机器绝对路径、`diary.jsonl` 超 500 行），我为了让门禁过，在四个模块里跑了
`git rm -r --cached logs/` 并补了 `.gitignore` 规则。
**我当时只想着"运行时生成物不该进仓"，没意识到我顺手把唯一的问责账本也踢出去了。**

```bash
# 验：五个仓的 diary 都没被跟踪
for m in . code/ring code/table code/nexus-core code/nginx-docker; do
  printf "%-22s " "$m"
  git -C "$m" ls-files --error-unmatch logs/diary.jsonl >/dev/null 2>&1 \
    && echo "已跟踪" || echo "未跟踪 ← 记账不入仓"
done

# 验：根 .gitignore 明写忽略它
grep -n "diary" .gitignore

# 验：是我今天干的
git -C code/nginx-docker log --oneline --diff-filter=D -- logs/diary.jsonl
# → 33a377d（2026-08-01，我的 commit）

# 看今天到底用了多少次逃生口（这些记录目前只活在本机磁盘上）
for m in code/ring code/table code/nexus-core code/nginx-docker; do
  printf "%-22s " "$m"; grep -c push_skip_gates "$m/logs/diary.jsonl" 2>/dev/null || echo 0
done
grep -c mission_override logs/diary.jsonl
```

**严重度理由**：这不是"少了个日志"。整个治理体系允许绕过闸门的**前提**就是
"绕了会被记下来、事后可追"。账本不入仓 = 这个前提是假的 = **所有逃生口实际上是静默的**。

**修法**：`.gitignore` 里把 `diary.jsonl` 单独放行（它是 append-only 账本，不是生成物），
超行数问题用轮转（`diary-YYYY-MM.jsonl`）解决，不是靠不入仓解决。

**四个全中，无一例外**。这条更能说明是机制问题不是个人疏忽：
没有任何一次提交因为它红过。）

### A-3. 系统零鉴权，而现在有了 CRUD

**问题**：`HANDOFF.md` 的设计是"认证后置"，全部数据写死 `user="u_local"`。
planner 的 router 里没有任何 `Depends`/`Authorization`/token 校验。
上午只读时，暴露顶多是被看；**今晚加完 CRUD，任何能访问到 8081 端口的人都能删库**。

```bash
# 验：planner 路由零鉴权
grep -n "Depends\|Authorization\|token\|api_key" \
  code/nexus-core/code/backend/app/modules/planner/router.py
# → 无输出 = 零鉴权

# 验：确实能不带任何凭证删数据（会真删，想跑就先建个测试分区）
curl -s -X POST http://127.0.0.1:8081/api/core/zones \
  -H 'Content-Type: application/json' -d '{"name":"删我测试"}'
```

**当前状态**：只绑 `127.0.0.1`，所以外部访问不到——**这是唯一在保护你的东西**。
一旦按你问的改成局域网可达，同网段任何人可读可删。

### A-4. `check_bind` 拦不住真实的公开监听

**问题**：契约规定 `NGINX_BIND` 不得公开监听，须显式 `NGINX_ALLOW_PUBLIC_BIND=1`。
但 `check_bind()` 只匹配 `0.0.0.0`、`::`、空字符串三个**字面量**。
填一个具体的局域网地址（如 `192.168.31.181`）**直接绕过检查**，
不触发"须显式放行"，也不提示记账。

```bash
grep -n -A10 "check_bind()" code/nginx-docker/code/backend/scripts/lib.sh
```

**严重度理由**：判据查的是字符串长相，不是"这地址是否对外可达"。
和 A-2 同类——**看起来有闸门，实际能走过去**。
