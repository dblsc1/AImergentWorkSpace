# 裁决 · `index.html` 1280 行的行数豁免与技术债

- 日期：2026-07-28
- 提出者：CFO arbiter
- 关联任务：`root-upstream-vault-260728-204450-674`
- 状态：**已落地（保险柜层）／待落地（模块层）**

## 事实

| 文件 | 行数 | 上限 | 超出 |
|---|---|---|---|
| `agents/reference/upstream/index.html` | 1280 | 铁律 9 = 500 | 2.56× |
| 同上 | 1280 | HANDOFF §8 第八条 = 300（下层加严） | 4.27× |
| `agents/reference/upstream/project-task-contribution-ring.html` | 251 | 300 / 500 | 未超 |

## 裁决

**存量导入，登记技术债，不硬拆。**

理由三条：

1. **拆分是改造，不是入仓。** 在保险柜里拆分会让仓内内容与上游原件的 SHA256 对不上，
   指纹随即失去意义——而指纹正是铁律 22 要求留的那个东西。保住原件与重构代码是
   两件事，混进一个动作就两件都做不干净。
2. **铁律 9 原文给了口子**：「遗留例外必须有精确豁免和技术债」。本条就是那份精确豁免。
3. **现在没有可靠的拆分依据。** HANDOFF §11.1 已经写明 `index.html` 要从 localStorage
   迁到 API、`progress` 从手动值改为计算值。这次重构本身就会重排文件结构；
   先按当前形态拆一遍、再按 API 形态拆第二遍，是纯浪费。

## 豁免边界（不是无限期免死金牌）

- **本裁决只豁免"保险柜里的原件"**，即 `agents/reference/upstream/` 下的只读快照。
- 根仓的行数门禁**当前不扫描该路径**：`scripts/gates/run-gates.sh` 在存在 `code/` 目录时
  只扫 `git ls-files -- code`。所以保险柜落地不需要任何豁免文件，**门禁是真绿，不是被绕过的绿**。
- **模块层另算**：原件派生进模块 `code/frontend/` 后，模块仓的同一门禁会扫到它。
  届时必须在该模块的 `review/reviewcode/size_exempt.txt` 里登记**精确路径**
  （`is_exempt` 用 `grep -qxF`，只认逐字符相等的整行，不支持通配），并在模块
  `AGENTS.md` 的「已知坑」写明豁免理由与偿还条件。**豁免写在模块仓，不写在根仓。**

## 偿还条件（满足即豁免作废）

派生文件在模块内**第一次因功能需求被实质修改时**（即 HANDOFF §9.1 切片 2
「planner CRUD + views/tree → index.html 弃 localStorage 改 API」落地时），
必须同时完成拆分至 ≤300 行/文件，并从 `size_exempt.txt` 删除该行。

换句话说：**只要没人动它，它可以一直是 1280 行；谁第一个动它，谁负责拆。**
这条把偿还绑在"反正要重写这个文件"的那一刻，成本接近零；
绑在日期上则一定会到期后再顺延一次。
