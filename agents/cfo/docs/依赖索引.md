# 项目级依赖索引

> **写属主**：CFO arbiter（角色卡职责 5）。模块 arbiter 维护自己的 `provides` / `consumes`；
> 本文件是**跨模块的汇总视图**，用途只有一个：**契约要改时，一眼找到全部消费方。**
>
> 漏登记的模块在变更评审里是隐形的——改契约的人不会知道它存在，
> 而它会在合并之后才炸。新增模块必须同步本表（铁律 11）。

**「闸门已实证」的含义**：不是"配了 origin"，而是**故意造了该被拦的推送、确认它真拦住**——
无 lease 推 `feat/init`、直推 `main`、伪造 `AIMERGENT_PUSH_LEASE=1` 三条路径全部被拒，
事后查远端 ref 数为 0。**配了远端却没验过，等于换个地方标「未验证」。**

**「本地模式·未验证」的含义**（`agents/reference/新模块与新项目开设指南.md` 第 71 行）：
未配置远端 **不等于** 该项豁免。此时 `pre-push` hook 一次都不会触发，
铁律 15（fetch-then-push、非 fast-forward 拒绝）**从未被检验却以为已生效**。
配好远端后必须回来补验真实 push 与 remote tip，并把本列改成实际远端地址。
