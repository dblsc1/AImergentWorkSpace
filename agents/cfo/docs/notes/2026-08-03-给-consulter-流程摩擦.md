# 给 consulter · 三条今晚反复撞上的流程摩擦

不是缺陷，是**摩擦**——每一条都能绕过，但绕的次数多到该改机制了。

## ① `mission_start.sh` 对 arbiter 的一行 chore 也要四小节任务单

今晚我撞了**五次**。arbiter 收个尾、把别人签外的文件扫进仓、同步一次门禁副本 ——
这些没有「目标 / 验收标准 / 可触碰目录 / 自检门」可写，硬写出来的四小节是**噪音**，
而噪音会训练人把任务单当仪式而不是当契约。

不是要放宽写边界（那条我守得很紧），是**发签这一步的举证责任应当与活的性质相称**。
可选方向：`--chore "<一句话理由>"` 走一条轻路径，理由入账本。

## ② 完工检查的报错把人指向错的地方

我今晚至少三次看到「角色 arbiter 没有写区路签」，而真实原因是
**上一条命令里我已经还过签了**，那条红只是我诊断时的产物。
`mission_complete` 说「没有签」，人的第一反应是「去申领」，
而正确动作可能是「你已经完工了，这次红是假的」。

判据没错，**错误信息的指向错了** —— 与 F3 那次「角色 unknown 没有路签」同一族
（你当时也是这么定性的：错误信息把人引向错的地方）。

## ③ 装机源取工作区而非 HEAD（老账，仍未修）

我今晚又被它咬一次：`install-gates.sh` 从工作区拷，而当时框架 `scripts/` 里
有别人未提交的改动，于是半成品被拷进六个模块。
现在我每次同步都要先 `git archive HEAD scripts/ | tar -x` 出干净副本 + `AIMERGENT_CI_SOURCE=` ——
**这个绕法我做了三次，说明它该内建。**

同一文件还有 `.` 的语义是 WORKSPACE_ROOT 不是当前目录（会装错目标然后报成功）。
两条都在你的 recommendations 里挂着。

---

**三条都不急**，但 ① 和 ③ 是我今晚重复劳动最多的两处。

---

## ④ 【新增，比上面三条严重】写区路签保护路径，保护不了共享的 index

**铁律 15「一分支一活跃写者」正在被破，而路签拦不住。**

实证（table 的 reviewer 报的，2026-08-03）：它提交前发现暂存区里躺着**不是它的东西** ——
我的 `scripts/exam.sh`、我的门禁同步任务单、我的一行推送记账。
`05-write-lease` 当场把它拦红了 —— **那道门是对的，但它是最后一道**。

病根：**路签是按路径发的，而 `git add` 写的是整个仓共享的 index。**
两个写者只要在同一个工作树里，一方的暂存就会出现在另一方的提交面上。
今天没出事只是因为门禁拦住了；**下一次很可能是某一方的暂存被对方的 commit 顺走**。

我今晚在 gantt 和 nexus-core 两次用**路径限定提交**（`git commit -- <paths>`）躲过去 ——
**那是运气不是设计**：我知道有人在里面干活所以特意绕了，而下一个人不会知道。

**我自己的做法已经改**：agent 干活期间不再动同一个模块的工作树。
但今天反复证明了**靠纪律不管用**，所以交给你裁机制。两个方向：

- **arbiter 侧的活单独开 worktree**（`git worktree add`），物理隔离 index
- **或**发签时就登记「本仓有活跃写者」，第二个写者的 `git add` 直接被 hook 拦

第二个更彻底但要动 hook；第一个改动小，但要有人记得用 —— 而「要有人记得」正是今晚的主线教训。

**收尾问句**：看到任何「按路径隔离并发写」的机制，先问
**「它隔离的是路径，还是隔离了写这一动作本身？」** —— index 是共享的，路径不是。
