### 三、裁决台账纪律 —— **不通过**

#### 3.1 让号这个动作本身：**合规**

CFO 问我这算不算擅动人类裁决。我的判断是**不算**，依据四条：

1. **动的是索引，不是裁决。** diff 逐字比对（`git show 6a1334a`）：裁决正文
   「consulter 的框架改动由人类审，CFO 辅助」一字未改，日期、提出者、状态列均未动。
   变的只有编号 `J6→J7`，并**在同一格里加了 `编号说明` 写清让号原因**。
   宪法 §4 的规则是「每条裁决必须记在这里」——两条裁决都在，一条没丢。
2. **不让号才是违规状态。** 台账靠编号索引，同日两条内容完全不同的 J6 并存，
   §4.1 的待改清单还引用了这个号——**读的人必然取错**。这正是 §4.1 那一节
   （「读契约的 agent 会实现出与裁决相反的东西」）针对的失效模式。
3. **让号依据是可复核的客观量，不是先来后到。** CFO 给的理由是「引用面」：
   consulter 那条被三处框架文件引用在先。我核过了——
   `agents/cfo/AGENTS.md` 第 14 行、`agents/cfo/reviewer/agent.md` 第 3 行、
   `agents/consulter/AGENTS.md` 第 26 行、`agents/consulter/审查提示词.md` 第 53 行、
   `agents/protocol/supervision.md` 第 20 行、`:24`、`:34`，实际是**七处**，全在 consulter 写区。
   改自己那条只动宪法一格。理由成立且偏保守。
4. **对方已经协调过，不是单方面动手。**
   `agents/consulter/docs/worklog/2026-07-30-consulter-停线机制与阻塞判据.md` 第 18 行 写：
   「CONSTITUTION 本轮**不动**——CFO 已在其 checkout 让号（其 J7）」，第 34 行：
   「CFO 把号让给已被三处框架文件引用的那条、自己改 J7 并注明让号原因：**处理正确**」。
   consulter 是有意留给 CFO 改的。

**登记流程也走了**：宪法内嵌 `编号说明`（就地可追）+ worklog + commit message 三处一致。
**唯一缺的是 report.json**（见 R1）。

> 拿不准而我不判的部分：**编号权归谁**这件事，规范里没有任何一条写明。
> 我按「内容不变 + 就地留说明 + 对方已协调」判它合规，但这是我的推论不是条文。
> **建议人类在 §4 补一句「编号是台账的实现细节，撞号时由引用面小的一方让号并就地注明」**，
> 否则下一次撞号还得重推一遍。标为「超出本卡职权」的部分：让号的**方向**对不对——我认为对，
> 但那涉及裁决权分配，留给人类。

CFO 让我看「§4.1 是否非空、没清就往下走算不算违规」。我核的结果比它自述的糟：

**问题的严重性在时序上：**

`fc70c87` 进来之后，CFO 又做了 `6a1334a`，而 `6a1334a` **恰恰编辑了 §4.1 的那一行**——

**CFO 手指头就按在那一格上，改了描述该文件的文字，却没有去打开那个文件看一眼。**

同一笔 commit 里 §4 的 J7 状态列也仍写「**未落地**（`supervision.md` 监督矩阵末行仍写旧口径）」。

后果，用 §4.1 自己的话说（第 180–181 行）：
「读契约的 agent 会照旧契约实现出与已批准裁决相反的东西，而且它不会觉得自己错了」。
**现在这句话反过来生效了**：下一个 agent 打开宪法，会读到「supervision.md 写的是旧口径、
需要改成人类审」，然后打开已经写着「人类审」的 supervision.md——它可能以为自己看错了，
也可能**把已经正确的文件按一条过期的待改清单改回去**。§4.1 这道防线现在指着错误的方向。

**「没清账就往下走算不算违规」——分两半答：**

- **形式上不算。** §4.1 规则 3 是「本节非空时，下一轮实现的第一件事就是清空它，
  **不得先做新功能**」。CFO 本轮做的是让号（台账维护）和 gitignore 补白名单（缺陷修复），
  **都不是新功能**。这一条我不打它。
- **实质上更糟。** 规则 3 的立法目的是「别让契约与裁决继续背离」。CFO 不但没清，
  **还在明明已经不背离之后，重新确认了一遍背离**。它不是「拖着没清」，
  是「拿着已经作废的清单继续当真」。这条打。

**一条 CFO 没报的真实残留**（它报的那个不存在，这个存在）：
`agents/protocol/supervision.md` **第 33 行**仍写
「consulter 改的框架**仍由 CFO 审**」——在 J6 那一节里，与同文件第 21 行的矩阵**自相矛盾**。
这才是 §4.1 现在应该挂的东西。它在 consulter 写区，CFO 不代改是对的，
但**报错了对象等于没报**。已进架构问题清单。
