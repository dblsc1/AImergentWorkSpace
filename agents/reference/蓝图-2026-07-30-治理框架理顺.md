## §1 目标与判据（不变的北极星）

目标：让长时间工作的 AI 可持续产出高质量代码，减少人的机械化测试，
防 vibecoding（不好维护/偏移原目标/原地打转）。

方法论判据（判例库精华，全部实证过）：
- **红/绿三问**：这检查会恒过吗？会恒败吗？**被测的是哪一份**（工作区/仓里/活钩子）？
- **自堵优于巡逻**：会过期的状态做成物理挡路的签/障/旗，不做定时提醒
- **散文没有半衰期**：教训必须变断言（作者本人一轮后就会原样再犯——实证）
- **不重复造轮子**：先查参考项目（Devin/OpenHands/MetaGPT/AgentCoder/agentic-os/MS-AGT），
  答不出「本场景哪里非自造不可」就用现成的
- **叫人是最贵的一步**：五类必叫，其余自决+记账（supervision.md）

## §3 沟通协议 [J9]

- **控制流/数据流分家**：打回/通过/升级全经 arbiter（保打回计数与独立性）；
  缺陷细节 programmer **直读 reviewreport 原文**（file:line+原始输出）；
  arbiter 在 comm.jsonl 只传路径+结论，**禁止摘要复述**；
  机械反馈（整合测试红绿）reviewer 落盘、programmer 自取。
- **指令双轨**：CFO 发意图级指令、尽量不读代码（token 贵）；arbiter 读代码后细化
  四小节；**CFO 原文逐字 passby**（任务单+派单 JSON 都带原文字段），漂移可 diff 可审。

## §10 独立成新框架：两面分层（用户 2026-07-30 提出）

```
<新项目>/
├── governance/（或 .aimergent/）  ← 治理面：agents(卡/协议/判例库)+scripts(checks/
│                                    hooks/lifecycle)+blockers/+logs/+蓝图
├── <模块仓们>                     ← 交付面：code + docker + nginx…各自独立 git（D3）
└── AGENTS.md                      ← 一行指针，兼容 agents.md 开放标准
```

- 社区同款：.github//.claude//.ruler/ 的「治理一个目录」模式放大版。
- 收益：治理面=可整体安装分发的单元（install-gates 的推广）；根白名单缩成三行。
- **红线**：代码侧留痕（worklog/report.json/handoff.md）**留在代码旁**（J3 colocation，
  收益已实证），治理面只收规范类文档。
- **测试计划**：三件冒烟——①单文件小功能全流程；②故意打回一次（验 J9 分家）；
  ③契约小改一次（验联动链）。三绿再上真活。
