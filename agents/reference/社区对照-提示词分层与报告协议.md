## A. 提示词分层级联

**社区做法**：agents.md 开放标准（OpenAI/Google/Cursor/Factory 采纳，Linux 基金会托管）
支持 monorepo 嵌套，冲突裁决＝「最近文件优先」；Claude Code 记忆级联
（enterprise→project→user + 子目录 CLAUDE.md）同理「越具体越优先」；Cursor rules
嵌套覆盖根规则，最佳实践「不要在子规则重述根规则——重复即漂移」；Devin
Knowledge/Playbooks 是语义触发召回非强制层级；AutoGen/CrewAI 只有扁平 system
message，无级联概念。

**关键差异**：社区裁决方向与我们**相反**——他们「就近覆盖」（下层可任意改写上层），
我们「法律层至上、下层只能加严」。社区无人做单调加严约束。生成物漂移有解：
Ruler、block/ai-rules 都是「单一源 → 生成各工具配置」，与我们拼接生成子代理 prompt
同构，但都靠重新生成保证一致，**没有字节一致断言**——我们的防漂移闸门更强。

**可行动**：拼接生成保留（Ruler 已验证）；抄 Ruler 的「生成文件头部 marker + 幂等
重生成脚本」；输出面兼容 agents.md 标准（已做）。

## B. AI 间结构化报告

**社区做法**：Google A2A 定义 Task/Message/Artifact——Artifact（最终交付物）与对话
消息分离，是与 report.json 最接近的公开协议，但锚定 URL 和 schema 不锚 git；
LangGraph checkpoint 每步状态快照成审计链可回放；OpenHands 事件流 append-only
不可变、重放即重建（与 diary.jsonl 同构）；Anthropic 多代理用 orchestrator 回收
压缩摘要；Cognition《Don't Build Multi-Agents》主张交接必然有损、解法是专门的
压缩模型提炼关键决策。

**关键差异**：「交接报告绑 git 证据（base/head/changed_files + Git 核验收货）」与
「objections 异议作为一等数据字段」**未找到公开先例——独有**。社区治字段膨胀三招：
压缩摘要非全量转述；payload 与消息分离（A2A Parts/Artifact）；工具响应 token 上限。

**可行动**：git 锚定保留（真差异化）；治膨胀抄 A2A——报告本体只留裁决字段、
大块证据外链仓内文件路径（blockers/ 便条已是此形态，推广）；diary.jsonl 可抄
OpenHands 的事件因果链字段（哪个 observation 由哪个 action 产生）。

## C. shell 硬闸门

**社区做法**：强制层位置三层共识——PreToolUse hook（工具调用时，最早、反馈环最短、
LLM 推理链之外的确定性控制层）→ commit 时跑快检查 → 重活进 CI（慢闸门会教人
--no-verify）。「test the tests」已工具化：mutation testing（Stryker/mutmut/PIT）
自动注入变异验证测试真能变红、可设 CI 阈值——我们的「新断言强制红/绿点火」
正是手动 mutation testing。hook 自测社区停留在手工注入验 exit code 层面；
**门禁新鲜度比对、停线旗未见先例**。

**可行动**：写边界路签、密钥检查**前移一份到 PreToolUse hook**（保留 pre-commit
兜底，双层设防）；红/绿点火可引入自动变异（脚本随机破坏被测断言输入验必红）；
停线旗与新鲜度比对继续自研。
