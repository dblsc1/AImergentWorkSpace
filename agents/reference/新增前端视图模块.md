# 新增一个前端视图模块（可重复配方）

> **为什么有这份文件**：HANDOFF §1.2 要求「新增视图 = 新增一条读路径 + 至多一张新投影，
> **现有代码零改动**」。那句话管的是 nexus-core 内部；本文是它在**模块层**的对应——
> 新增视图模块必须是**照配方走一遍**，而不是照着前两个模块抄。
>
> 抄前一个模块是最常见的腐坏方式：抄的人不知道哪些是本质、哪些是上一个模块的偶然，
> 于是偶然被复制成惯例。**配方与索引在这里，模块目录里不留"参照物"。**

## 适用范围

四个前端（ring / table / gantt / garden）以及将来任何新视图。它们的共同形状：

- **纯静态页，零后端逻辑**（HANDOFF §4）。不许在前端模块里放服务端代码。
- **只读一条 `/api/core/views/*`**，不碰别人的库、不与其他前端通信（HANDOFF §2.1）。
  四个前端之间**没有任何通信路径**，它们只是同一份事实的四面镜子。
- 通过 nginx 挂在自己的静态路由下（HANDOFF §4 已定死，前端写死地址）。

## 配方（八步）

### 1. 建骨架

```
scripts/new_module.sh <view>
```

模块名用**视图名本身**（`ring` / `table` / `gantt` / `garden`），与 nginx 路由、
HANDOFF §1.2 视图表的命名保持一条线。不要叫 `frontend-ring` 之类——
前缀在四分区结构里是冗余的，`code/` 下本来就只有模块。

### 2. 验证门禁真的装上了（不要信打印）

`new_module.sh` 打印的「门禁 已安装」曾经在门禁根本没装时照常输出
（调用点是 `if [ -x … ]`，脚本改名后静默跳过）。名字已修，**沉默失败的形状仍在**。
所以这一步是**看，不是信**：

```
ls code/<view>/.git/hooks/            # 应有 pre-commit / commit-msg / pre-push
cd code/<view> && ./scripts/gates/run-gates.sh
```

**正确的失败长这样**：红在 `module_docs/contract.md 还没填实`。
那是待办，不是故障。若它直接全绿，或红在别处，先停下查门禁本身。

### 3. 填 `module_docs/contract.md`

前端模块的契约是**两面**的，两面都要写：

- **consumes**：本视图读的那一条 `/api/core/views/*`（见 HANDOFF §7.1），
  以及它依赖的响应字段。字段级写清楚——将来 nexus-core 改字段时，
  CFO 靠这个找到全部消费方。
- **provides**：页面对外暴露的渲染接口（如圆环的 `window.renderContributionRing(json)`）
  与静态路由路径。**这是对外行为的唯一事实**（铁律 4）。

### 4. 派生原件（如果这个视图已有存量前端）

存量 HTML 一律先在 `agents/reference/upstream/` 固化（铁律 22），再**派生**进
`code/<view>/code/frontend/`。**保险柜只读，不回写**——回写会让 SHA256 与上游对不上，
指纹立刻失去意义。派生时在模块 `AGENTS.md` 的「已知坑」记一行：来源哪份原件、改了什么。

没有存量前端的视图（gantt）跳过本步，直接对 mock server 开发（HANDOFF §9.1 第 2 步）。

### 5. 超限文件登记精确豁免

模块仓的行数门禁扫 `git ls-files -- code`，会扫到派生的前端文件。超 500 行的：

```
echo 'code/frontend/<文件>' >> code/<view>/review/reviewcode/size_exempt.txt
```

`is_exempt` 用 `grep -qxF`，**只认逐字符相等的整行，不支持通配**。
每条豁免必须在模块 `AGENTS.md` 写明理由与偿还条件，且**偿还条件绑在"谁第一个动它谁负责拆"**，
不要绑日期——绑日期的到期只会再顺延一次。

### 6. 配 `origin`，或如实记为「本地模式·未验证」

`new_module.sh` 建出来的模块**没有远端**。按 `agents/reference/新模块与新项目开设指南.md`：
**未配置远端 ≠ 该项豁免**——此时 `pre-push` hook 一次都不会触发，铁律 15
（fetch-then-push、非 fast-forward 拒绝）**从未被检验却以为已生效**。

两条路，必须二选一并写进 handoff/report，不许留空白：

- 配远端 → 补验真实 push 与 remote tip；
- 暂不配 → 该项记为**「未验证」**，配好远端后回来补验。

### 7. 在依赖索引加一行

`agents/cfo/docs/依赖索引.md`。**这一步不是文书工作**：
契约变更时 CFO 靠它找到全部消费方，漏登记的模块在变更评审里就是隐形的。

### 8. nginx 加静态路由

按 HANDOFF §12 的变量式上游写法，单服务下线不连坐。路由本身在 HANDOFF §4 已定死。

## 反面清单（做了就是腐坏）

| 别做 | 为什么 |
|---|---|
| 从已有前端模块 `cp -R` 出新模块 | 会把上一个模块的偶然复制成惯例。骨架的唯一事实源是 `code/_template/` |
| 在前端模块之间共享 JS / 互相 import | 铁律 8：模块只经契约依赖。四个前端**没有通信路径**是架构决定，不是还没来得及连 |
| 前端直连 nexus-core 以外的东西 | 同上。要新数据 → 找 views 模块加读路径，不要绕 |
| 在保险柜里改原件 | 指纹立刻失效。改造只发生在模块 `code/` 下 |
| 信 `new_module.sh` 的「门禁 已安装」 | 见第 2 步。这句话有前科 |
