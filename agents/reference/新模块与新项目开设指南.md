# 新模块 / 新项目开设指南

> 面向“快速开一个模块 / 网页项目 / 独立项目”的 agent。框架根指 clone 后的本仓顶层；本指南不假设它位于某个固定绝对路径。

## 一键脚手架

```bash
./ci/new_module.sh <相对 AIMERGENT_WORKSPACE_ROOT 的目标路径>
```

示例占位：

```bash
./ci/new_module.sh modules/example_service
AIMERGENT_WORKSPACE_ROOT=/path/to/workspace ./ci/new_module.sh experiments/example_app
```

脚本从框架根 `code/_template/` 复制骨架，替换模块名和框架相对路径，再以 `main` 分支初始化目标 Git 仓。**建模块的本质 = 复制唯一模板 + 填真实事实 + 按需叠加治理。**

## 通用必读包

| 资料 | 框架内路径 | 作用 |
|---|---|---|
| 项目级铁律 | `AGENTS.md` | 工作模式、边界、协作流程 |
| 文档地图 | `agents/reference/manual/文档地图.md` + `agents/reference/manual/README.md` | 导航与文件夹速览 |
| 设计原因 | `agents/reference/1 structure/README.md` | 权威架构说明 |
| 模块骨架 | `code/_template/` | 新模块结构唯一事实源 |
| 角色基线 | `agents/roles/{arbiter,backend,frontend,reviewagent}.md` + `orchestration.md` / `report-schema.md` | 模块角色卡薄引用 |
| 项目级角色 | `agents/cfo/AGENTS.md + agents/consulter/AGENTS.md` | 跨模块裁决与架构顾问 |
| 门禁工具 | `scripts/` | 建模块、安装 CI、检查、合并 |

三条必须讲清的纪律：

1. **唯一事实源**：改骨架只改 `code/_template/`，不改副本后再倒灌。
2. **级联方向**：框架/项目级 → 模块级 → 角色级；完整治理下下层只能加严。
3. **文档 DRY**：worklog / report.json / diary / handoff 各承载一个时间维度，各一写属主。

## 轻量模式

适用于突发想法、单人、无外部消费方：

- 保留：脚手架、Git、`.gitignore`、`.env.staging.example`、`code/` 和项目自检。
- 可暂缓：CFO、独立 reviewagent、worktree、canonical report、契约索引和远端合并门。
- 一个 agent 可兼任实现与自检，从模块根 `AGENTS.md` 与 `module_docs/rules.md` 接单，不加载单一受限角色卡。
- 一旦有其他模块/客户端调用，先把 `module_docs/contract.md` 填成真实对外契约。

一句话：轻量 = `new_module.sh` + 直接写 `code/` + 真实自检；骨架已保留原地升级能力。

## 完整治理模式

适用于多人、多模块、有外部消费方或需要独立审计的项目：

1. 在 `module_docs/rules.md` 选 `governed`，填技术栈、代码分区和确定性自检命令。
2. 填真实 `contract.md`：`provides`、`consumes`、路由、数据属主、env 边界和变更记录。
3. 根据实际需要激活 CFO + module arbiter + frontend + backend + reviewagent，角色卡薄引用框架 `agents/roles/`。
4. 运行 `./ci/install-ci.sh <module-path>` 安装确定性 CI 与 hooks。
5. 首个切片走“开单 → 实现/自检 → 固定 candidate → reviewagent exact 独审 approved → merge gate”。

如模块将部署到网关，由项目填写真实 nginx 入口；`.env.staging.example` 只写变量名与无敏占位，真实值通过运行环境注入。

## 验收清单（7 条）

> 每条前的 `[模块]` / `[根仓]` / `[两者]` 是**作用域**——跑清单前先确认你在验哪个对象，
> 否则会拿模块的判据去验根仓（已实证：因此误判过一次假红）。完整治理执行全部 8 条。轻量模式可暂缓多角色、canonical report、独立审核和远端合并，但 Git、`.gitignore`、密钥不入库和项目自检不可裁剪。

1. `[模块]` **结构齐（J3 布局）**：`codeagent/`（arbiter 长期单例 + programmer/、reviewer/ 实例容器）+ `module_docs/`（五件 + `worklog/` + 迁入的 `report.json` 落点）+ `code/`（每子文件夹 `handoff.md` + `worklog/`）+ `review/` 全在，空目录 clone 后不丢。
2. `[模块]` **占位清零**：已生成模块中 `{{MODULE_NAME}}` 和 `{{FRAMEWORK_ROOT}}` 零残留。
3. `[两者]` **级联可解析**：模块/角色 `AGENTS.md` 只引用当前框架内部的 `AGENTS.md`、`agents/roles/`、`scripts/`，无作者机器绝对路径。
   判据在两处各有一份实现：`scripts/gates/run-gates.sh` 与模块的
   `review/reviewcode/run_all.sh`（源自 `code/_template/`）。**改一处必须同步另一处**——
   2026-07-30 只改了前者，后者没动，于是整体一直红、推送被迫走逃生口，
   直到 2026-08-01 才补齐（障签 abspath-second-copy）。
   两处都豁免**注释行**与 `worklog/`、`review/reviewreport/` 这类 append-only 叙事记录：
   判据防的是「**用到的**路径换台机器就废」，文档里**讲**这个坑没有可执行伤害。
4. `[模块]` **契约成文**：有外部消费方时，`contract.md` 是真实事实，无语义占位。
5. `[两者]` **门禁绿 —— 且必须确认它真的验了东西**：模块 `scripts/gates/run-gates.sh` 与 `run-tests.sh` 通过；本任务有 canonical report 时通过 `check-report-schema.sh`。**"退出码 0"不等于"验过了"**：`check-report-schema.sh` 必须打印出被验报告的路径行（`✅ report schema: <path>`）；只打印总结行 = 本次一份都没验，按**未通过**处理（成因通常是直接在 `main` 上提交导致任务区间为空）。
6. `[两者]` **归属 + 落地**：完整治理的 commit 有唯一 `Agent-Attribution`。**不得伪造或新建远端来凑测试**；但**未配置远端 ≠ 该项豁免**——本项此时记为「未验证」并写进 handoff/report，不许当作已通过。配置远端后必须补验真实 push 与 remote tip。
7. `[模块]` **依赖合规**：只依赖已发布契约，无跨模块直连。
8. `[根仓]` **框架自身走得通（clone 后一次性验收）**：见下节「根仓开工」。**前 7 条查的是"用框架建出来的模块对不对"，本条查的是"这个框架自己能不能被走一遍"**——历史上丢规范正是丢在这一条没人查。

## 根仓开工（clone 之后、动任何业务之前）

框架根**不是配置目录，它是一个真实的受治理 Git 仓**（铁律 20）。clone 完先把它自己立起来，否则整个项目会在"有规范、无门禁"的状态下裸奔：

```bash
./ci/install-ci.sh .          # ① 给根仓自己装门禁与 hooks（支持 . = 根仓）
git checkout -b feat/<主题>   # ② 根仓工作同样走分支，main 只经合并门更新
./ci/gates/run-gates.sh       # ③ 跑门禁——并确认它打印了被验对象，不是空跑
```

四条必做，缺一条就会复现已知事故：

| 必做 | 不做的后果（均为已实际发生） |
|---|---|
| `install-ci.sh .` | 根仓无 hooks、无 CI，铁律 14/15 全程不生效 |
| 根仓工作走 `feat/` 分支 | 直提 `main` → 审核门失效 + `check-report-schema.sh` 全程空跑假绿 |
| 配 `origin`（或明确记为"本地模式·未验证"） | `pre-push` hook 一次都不会触发，铁律 15 从未被检验却以为已生效 |
| 按需启用 `CONSTITUTION.template.md` | 人类已批准的裁决无处安放，下一个 agent 照旧契约实现出反向结果 |
| 新增根级文件后 `git ls-files <路径>` 确认被跟踪 | 根 `.gitignore` 是**白名单**，会静默吞掉未登记的新文件——写了、commit 了、却根本没进仓 |

## 冷启动读取顺序

轻量：模块 `AGENTS.md` → `module_docs/rules.md` → `code/`。

完整治理：框架根 `AGENTS.md` → 模块 `AGENTS.md` → 框架 `agents/roles/<role>.md` → 模块角色卡 → `module_docs/` → 所依赖契约。
