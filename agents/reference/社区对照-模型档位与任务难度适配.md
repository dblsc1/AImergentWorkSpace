# 社区对照 · 模型档位与任务难度适配（定量路由）

> 「PreToolUse 前移层 / 派单 json 字段」那一铲的设计输入。

## 1. 社区共识：提醒是最弱的一档，模型选择要搬出大模型的记忆

由强到弱三档做法：

1. **声明式绑定（主流，治本）**：模型档位写死在代理定义里，orchestrator 只选
   「叫哪个代理」，不选「用什么模型」。
   - Claude Code 子代理 frontmatter `model: sonnet/haiku`；内置 Explore/Plan 默认便宜档；
     `CLAUDE_CODE_SUBAGENT_MODEL` 环境变量一刀切所有委派档位
   - Aider architect/editor 模式：强模型出方案、弱模型写编辑，绑在启动配置，会话中无人做选择
   - Router 模式：便宜模型做分类路由，贵模型只干被路由到的活
2. **机器层执法（hooks）**：软执法= PreToolUse 检测到 orchestrator 亲自动手时注入
   system-reminder（Claude Code 官方用递进式：沉默→暗示→警告→强提醒）；
   硬执法= hook 退出非零直接拦。
3. **提示词提醒**：公认最不可靠——与本框架 N2 判例同形状（散文教训管不住一轮后的作者本人）。

## 2. 简化版（当前采纳）：派单 json 的 `complexity` 字段

社区现成范式：task-complexity-router（Claude Code 生态 skill）+ Triage 论文
（arXiv 2604.07494，按代码质量信号路由 SE 任务到成本档）。
判据不是单看行数，是 **行数 × 文件数 × 有无新设计决策** 三个便宜信号：

| 档 | 判据（满足全部） | 模型 |
|---|---|---|
| `simple` | 预计 diff <100 行；动 1–2 个文件；无新设计决策（查找/机械修改/照模板写）；有一条明确验收命令 | codex / haiku 档 |
| `normal` | 100–500 行；单模块内 ≤5 个文件；设计已定只需实现+配套测试 | sonnet 档 |
| `hard` | >500 行，或 ≥6 个文件，或任一：跨模块/改契约、新架构决策、原因未知的调试、验收靠肉眼 | opus 档 |

- 社区文件数阈值原话：1 个文件→降档，2–5 个→不动，6–10 个→标准档，11+→复杂档。
- 500 行是 normal 的**上限**而非 simple 的：超 400 行的 diff 人审质量陡降（PR size 研究）。
- 实证不对称：**代码越干净，便宜模型越能改**——遗留/混乱区域的任务手动升一档。
- 拿不准往上取（升档只费钱，降档伤质量）。

**派单模板提醒句（一句话版）**：
派单必填 complexity（simple<100行1-2文件无设计｜normal<500行单模块｜hard 其余）；
simple→codex/haiku，normal→sonnet，hard→opus。拿不准往上取。

## 3. 完整版备用：级联 + 计量闭环（未落地，设计存档）

事前预测难度需要训练路由器（RouteLLM，需千级偏好数据），本框架规模不可行；
可行的是**级联（cascade）**：默认便宜档→机器验收→不过再升档。FrugalGPT 三级级联
省 98% 成本，RouteLLM 省 85% 保 95% 质量。

映射：arbiter 的 tier 字段=事前粗分类器；门禁+测试+reviewer=质量评估器；
「无打回一律 sonnet、打回复审升档」+「打回 2 次超限升级」=升档策略。缺的只是计量环。

校准阈值（社区数字）：
- **25% 盈亏线**：某任务类在便宜档失败率超 ~25%，「便宜试+强档重做」总成本反超直接钉强档
  （0.3+0.9=1.2 次请求 vs 0.9）→ 过线上调默认档。
- 一次通过率 ~100%（样本≥10）=配置过剩可试降档；<70% =配置不足升档。
- 按「每个**通过**任务的成本」计费，重罚昂贵的失败（AgentMeter）。
- 遥测必须按 model_id 分桶，否则「省了钱」掩盖「质量静默退化」。

自纠正机制（非对称自动化）：
- 路由表成数据入仓（任务类→默认档），每次调表引用 stats 输出，reviewer 核记账；
- 升档全自动（只费钱）；**降档只许机器提案+金丝雀**：降档后前 N 单强制全审，
  掉线自动回滚；且只在机器强验收覆盖的任务类降档；
- 防震荡：迟滞带（升 25%/降 5%，中间死区）+ 最小样本 10 + 每类每周期最多动一档；
- 人只改阈值/规则，不出现在每次调档。

## 4. 质量怎么评（三层裁判互相校准）

实证：**无人工校准的 LLM 打分「与任何可测量的东西不相关」**；带 rubric+证据义务+
人工抽检后与人类一致率 ~92%。

| 层 | 信号 | 作弊面 | 加固 |
|---|---|---|---|
| L0 机器硬信号 | tests/lint/build/契约测试 | 自己写的测试不咬人 | mutation score（红/绿点火=手动 mutation testing）、改动行覆盖率增量、消费方契约测试 |
| L1 独立评审 | reviewer verdict | judge 漂移、橡皮图章 | 审法卡=rubric；**定期人工抽检 judge 本身**，一致率掉线修提示词 |
| L2 滞后真值 | 缺陷逃逸率（bisect 回溯引入单）、churn（N 天内被重写的行）、handoff 误导次数 | 无（就是 ground truth，只是来得晚） | 用它定期校准 L0/L1 |

统计口径不造合成质量分——用「一次通过 且 零逃逸」二元判定进闭环。

## 5. 从数百个报告提信息（报告是仪表，不是证据）

社区框架=metrics vs traces 分层：report.json 是 metrics（供聚合），
comm.jsonl/diary.jsonl/会话 transcript 是 trace（供钻取），信息没丢，别把报告写厚。

1. **聚合只碰结构化字段**：脚本扫报告出分布，零阅读。
2. **尾采样精读**（tail-based sampling 生产范式）：异常 100% 精读（2 次打回/升过档/
   escalation 非空/token 时长离群）+ ~5% 随机样本抓 unknown unknowns。
   这是 consulter 模式监督的机械化选样器。
3. **三源对账比单源值钱**：report.json（自述，会橡皮图章）× diary.jsonl（机器事件，
   不说谎）× git（ground truth）× reviewer verdict（独立方）。**矛盾本身是最有价值的
   信号**（自述绿 × diary 门禁红 = 撒谎式成功指纹）。
4. 信息损失长效解：尾巴钻取发现报告没承载的信号→给 report-schema 加字段/枚举
   （schema 按判例演化）。objections 字段是现成抗损失通道。本框架量级 trace 全留不采样。

## 6. 成本账：token 换人时

- **token 用量升**：多 agent 比纯聊天多 ~15×，比单 agent 多 3–10×（上下文复制、
  协调消息、报告汇总）。治理层（独立 review+门禁+留痕）落在此区间。
- **美元可对冲**：模型分档（Haiku 比 Opus 便宜 ~15×/token）+ 结构化治理比 ad hoc
  省 ~30% 推理成本 → 成本可打平或更低，token 总量仍是升的。
- **省的是人时**：大项目 vibecoding 的真实成本在事后——人工机械测试、逐行盯 review、
  返工追查、不可维护的复利。治理把机器可判的全部下放，人剩五类必叫事+定期抽检。
- 无可信的「省 X%」总数（vibecoding 返工成本无人测准）；反向实证：无结构地用 AI，
  资深开发者在大仓里反而变慢（METR 类研究）——**省不省取决于验证是不是机器扛的**。
- 小项目买不回本（轻量模式的存在理由）；大项目买得回：人时单价与返工复利远高于 token。
