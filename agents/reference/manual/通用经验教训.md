# 通用经验教训

> 从实战沉淀的**跨项目通用**踩坑与纪律，凡与具体业务/模块无关、换个项目仍成立的才收进来。项目特有教训写各模块 `rules.md` / worklog，不进本表。

## 报告与门禁（完整治理）

1. **base 用完整 40 位 SHA**：`scripts/gates/check-report-schema.sh` 的 `git.base` 要求完整 40-char hex，短 SHA 直接被拒。
2. **推送前先本地跑 schema 门**：`AIMERGENT_REPORT_BASE=<40hex> AIMERGENT_REPORT_HEAD=$(git rev-parse HEAD) bash scripts/gates/check-report-schema.sh`，把报告格式错在本地拦掉，别等 PR CI 才发现。
3. **`review_target` 是 reviewer/consulter 专属**：arbiter/backend 报告用 embedded-self-v2（`git.head="SELF"`、`diff_mode="contains"`），**不得**带 `review_target` 块；reviewagent 才用 `review_target`（`diff_mode=exact` + `changed_files` == base..head 的 no-renames diff 集合）。
4. **任务单固定提醒携带 standing 闭合标记**：worker 极易丢掉 base 携带的 standing tech_debt 闭合标记而被打回。开后端/前端单时固定加一行「report.json 必须携带 base 的 standing 闭合标记，别丢」。
5. **合并门在 merge，不在 commit**：commit+push 只形成远端 candidate；reviewer approved 后才经 `merge-to-main.sh` 合 main。别把本地 hook 表述成远端硬保护——私有仓服务端 branch protection 可能尚未启用。

## 命令与工作目录

6. **命令在对的仓根跑**：`<vcs> pr create` 必须在**模块仓目录**跑（在框架根跑会报「main 与分支间无提交」）；`scripts/merge-to-integration.sh` 必须从**框架根**跑。跑错目录的报错常被误读成"没改动"。
7. **交接前核实远端落地**：宣布 agent 完成、释放写入位、派下一个之前，核远端 tip（`git ls-remote`）== 该 agent 报告的 commit；未核实落地不交接（堵"判定结束但 commit 还在飞"的窗口）。

## 部署与运行时

8. **反向代理的 upstream IP 漂移**：长驻反代（如 nginx）通常只在启动时解析一次 upstream 主机名。容器化后端被重建会拿到新 IP，反代仍用旧 IP → 对该服务全部代理请求 502。**重建任何被代理的后端后重启反代**，或给反代配 resolver + 变量式 proxy_pass 动态解析。
9. **会话特性在登录时烘焙**：若鉴权把权限/特性快照进会话，改班级/角色权限**不影响已激活会话**，需重新登录才生效。排查"明明开了权限却仍报无权限"先看会话缓存，别急着改配置。

## 里程碑纪律

10. **里程碑跑文档一致性审计**：block/wave 合并、契约变更、模块增删、冷启动交接前，专门扫文档漂移——过期看板/状态、失效的报告证据、handoff/索引掉队、契约内部自相矛盾、脚本里写死的过期状态。可代码化的做成脚本常态跑。

## 并发写入

11. **「申领 → 使用 → 释放」三段式，释放那一步必须有人**在关键路径上执行。本项目实证：写区路签的 `--release` 是纯自愿的事后动作，全仓没有任何地方调用它 —— 于是派活方派完活走人，签永久挂着，被卡的一方**沉默地重试**。同一个错一天犯了三次（ring / table / gantt），每次事后 worklog 都写「以后记得还签」然后又犯。**靠记性无效。**
    三个独立缺陷各修一层：① **无过期** → TTL + 开工先回收（`scripts/lib/lease.sh`，默认 2h）；② **释放不在关键路径** → 完工即自动还（本仓 `mission_complete.sh` 就是 pre-commit 主体，不能在那还，落点待定）；③ **被卡方沉默** → 拒发必须说清谁 / 多久 / 什么任务 + 三条出路。
    **回收必须打印回收了谁**：忘了还签会卡住人（吵闹），静默回收会让双写发生（安静）—— 后者更危险。**未知不等于过期**：判不出年龄的签（无 meta）不许回收，只许提示强收。
    **粒度过粗也算病**：arbiter 持 `codeagent/` 挡住了 `codeagent/programmer/docs/`，而它真正要写的只是一张任务单。一旦签开始串行化正常并发，说明写区划分错了。

    ▎ **给复审的收尾问句**：看到任何「申领 → 使用 → 释放」的三段式，先问
    ▎ **「释放那一步，是谁在什么时候一定会执行？」** 答不上来就是下一次卡死。
