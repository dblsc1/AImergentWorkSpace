# consulter 判例库（已付过学费的坑）

> 每条都来自本项目或前身项目的真实事故。审核时对照；新事故往下追加，不删旧条。

## 完整性类

- **假绿最危险**：门禁退 0 ≠ 验过。check-report-schema 曾在空区间上零验证报绿，
  掩护了 10 个 commit 直提 main。**必须看到它打印被验对象**。
- **留痕落点三杀**：目录不存在（agent 就不写）、写在 /tmp（会话结束蒸发，9 份报告全灭）、
  被白名单 gitignore 静默吞（写了 = 没写，踩过 4 次）。核留痕先核落点。
- **撒谎式成功**：脚本写产物不验落点，被吞了照常打印 ✅。见 emit.sh 的 assert_trackable。
- **口头完成不认**：Codex 曾报"迁移好了"，实际核心任务整个没做。核 commit SHA、核 remote tip。

## 修复质量类

- **修类不修实例（铁律 23）**：A1 占位符自毁、install-gates 装错目录、merge 脚本引用死路径,
  全是同一形状——字符串替换式改动,静态 grep 看不出"引用物已不存在"。修完必须留断言,
  否则下次重构原样复活。
- **半做比不做危险**：GAP-1.2 只改了一份契约,另一份留着相反规则,下游以为已对齐。
  裁决落地必须全量清扫 + grep 反查留痕。

## 认知偏差类（审 AI 的产出时专用）

- **过度自责掩盖框架缺陷**：自责 ≠ 归因。arbiter 曾把框架缺陷全揽进自己检讨,
  显得负责,代价是下一个人继续踩。审报告时问:这条"违规"的根因真在执行者吗?
- **确认即停**：读到符合假设的证据就停止阅读,三次事故(A1-5 正则、--hook-only 顾虑、验收误扫)。
  下断言前先跑一遍看**全部**命中。
- **自我豁免**："根仓不算模块"、"契约是特例所以升档"——为想做的事发明规范外例外,
  一个模式能生成无限条违规。
- **指令无人审**：执行者产出有 reviewer,编排者的任务单没人看,错误率反而更高
  (一轮四次被执行者纠错,零次被机制抓到)。审 arbiter 时重点看任务单质量与 objections 记录。

## 流程类

- **先审后推**：审绑本地 commit(不可变、有 SHA,足够);被打回的活不上远端。
- **续用 > 重开**：打回循环重开 agent = 冷启动重读全部上下文,实测占一轮消耗 31%。
- **判断题不做硬闸门**：硬闸门只配事实题;判断题硬拦会逼人用逃生口,逃生口用滥整套闸门就废。
- **逃生口必须记账**：override 可以用,但必须在 diary 可见。审时查 override 次数与理由。
- **框架修改回框架仓**（GitHub v5 分支）,不在 CFO 工作树里动手;实例修复才在工作树。

## 字面量类（CFO 2026-07-29 提炼，第三次复发才看清）

**凡是「报告一个关于字面量的缺陷」的文档，都会成为那个缺陷的新实例。**

实证三次：占位符 token 先后出现在①模板检查脚本自身（被 replace_token 吞掉）、
②heredoc 展开、③上报该缺陷的 report.json 与 worklog 里（逐字引用）。
每次都以为修的是"那一处"，其实是这个形状换了个载体。

**判据**：讨论 token / 占位符 / 敏感字面量的**文档**，与**检查脚本本身**是同一条规矩，不是两条。

## 仓型与路签类（2026-07-29 CFO 实报后按类修）

- **判据仓型不匹配已四次实证**（run-gates 装进模块恒红、mission_start#4、checks/12、checks/60）。
  修法已抽公共件：`lib/paths.sh` 的 `repo_is_module` / `framework_root` / `resolves_here_or_framework`。
  **新写任何 check 先问「我在哪种仓」，一律用公共件，不再各自手写仓型判断**（selftest#43 盯着）。
- **单文件申领不到路签**：norm() 强加尾斜杠 + 05 前缀匹配 → `.gitignore` 永远匹配不上；
  与白名单 gitignore 叠加＝静默丢数据路径（白名单行加不上→新根级目录被吞）。
  修法双保险：norm 对已存在文件不加斜杠 + 05 接受精确相等。**通用形状**：
  「前缀匹配」类判据必须自问——单文件、精确相等这两种输入它认不认。
- **红/绿扰动前先看工作区**：本轮用 `git checkout --` 恢复被扰动的文件，把**未提交的修复**
  一起冲掉了（绿测因此假红才发现）。扰动含未提交修复的文件，恢复只许用备份副本，不许用 git。
写法一律拆开：`'{{'"NAME"'}}'`、或转义、或只描述不逐字引用。

**审的时候怎么用**：看到一份文档在讲某个字面量，先问「这份文档自己算不算那个字面量的实例」。

## 恒定答案类

**一条永远给同一个答案的检查，等于没有这道门。** 已实证四种形态：
- 空区间假绿：`merge-base == head` 时 diff 为空，零份验证却退 0
- landed 恒真：快照含脚本自己的 diary 写入，写一行就算"活落盘了"
- 模块门禁恒红：`run-gates` 引用的 `check-references.sh` 没被装进模块
- 判据仓型不匹配：照框架仓写的检查装进模块仓，恒红

**审的时候怎么用**：对任何一条检查，追问两句 ——
**它在什么情况下会永远通过？在什么情况下会永远失败？** 两个答案都必须是"没有这种情况"。
反向验证（放入违规→变红，拿走→复绿）是唯一可信的证明，看代码不算。

**这条从今天起是硬要求，不只是审法**（2026-07-29，两任 consulter 共识）：
**新增任何断言/闸门/检查，同一逻辑变更里必须做一次红/绿反向验证并把真实退出码写进留痕。**
只写断言不点火 = 又一台没验过的烟雾报警器。已实证收益：#36 计数断言的红测当场
抓住了并行会话里全景文档的硬编码「23 条」。

**验证者自己的 $? 也会撒谎（同日实证三次）**：`cmd | tail; echo $?` 取到的是管道
末段的退出码——曾把真修复看成无效、把有效门禁看成恒绿、把被拒的 commit 看成已提交。
判退出码必须直取（`cmd >f 2>&1; echo $?`）或 `PIPESTATUS[0]`；
判 commit 成败只认 `git log`/`rev-parse`，不认回显。
