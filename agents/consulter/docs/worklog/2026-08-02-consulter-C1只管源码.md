## 二、为什么同批动了模块模板（铁律 23：修到类）

`code/_template/review/reviewcode/run_all.sh` 第 33–35 行原本有**第二份行数判据**：

```
# 3. 全类型行数（补 gate 的后缀盲区）
over=$(git ls-files -z | xargs -0 … [ "$(wc -l < "{}")" -gt 500 ] …)
[ -z "$over" ] && ok "无超 500 行文件" || bad "超 500 行: …"
```

三个问题，任一个都够删它：

1. 它写的规则**和 C1 不是一套**（全类型、一档、>500 直接硬拦），对 `.md` 照拦 —— **与 D16 正面冲突**。
   只改 `run-gates.sh` 而留着它，等于人类的裁决在模块里不生效。
2. 它的存在理由（注释里写着「补 gate 的后缀盲区」）**在 2026-08-02 那轮已经消失** ——
   盲区是当时那个坏白名单造成的，那个已经修了。
3. 判据两份实现 = 迟早分叉。**同一个文件的第 23–26 行就记着 abspath 判据分叉造成的
   `abspath-second-copy` 事故**（只修了 run-gates 那份，模块那份没动，四模块推送被迫走逃生口）。

删它会少扫模块的 `review/reviewcode/`（`run-gates.sh` 模块模式只扫 `code/`），
所以**同批给行数 gate 单独加了扫描集** `size_tracked = tracked + review/`（仅模块仓）。
**没有并进 `tracked`**：禁默认值 / 禁止路径两道 gate 扫 reviewcode 会把判据自己写的样例
字符串当成命中 —— 模板的 abspath 判据显式排除了 `*reviewcode*`，是同一个道理。

### 断言是怎么防「旁因」的

CFO 上一轮定的通则：**任何「加了防御 + 断言它有效」的组合，都要问有没有一个碰巧同向的
旁因，能在防御被拆掉后仍然让断言绿。**

`.md` 不变红的旁因至少有三个：被当成二进制、被当成第三方产物、路径压根没进扫描集。
所以断言用的是 **同一份 1200 行内容、同一个目录、只改扩展名** 的一对 fixture ——
任何一个旁因都会让 `.sh` 那发也不红，两发一起挂。

外加一条**非常量**的计数断言：`docs/prose.md` → `docs/prose.sh` 前后，
`扫描 N 个源码文件` 的 N 必须**正好加 1**。
（只断言「输出里有『不在 C1 治理范围』几个字」是弱的 —— 那行是常量，
删掉被验逻辑照样印。这就是上一轮 `*"扫描 "*` 恒真那个坑的同一形状。）
计数行被删时该断言取到空串，`$(( 空 - 空 )) = 0 ≠ 1` → FAIL，**不是崩溃**（红 C 已实测）。
