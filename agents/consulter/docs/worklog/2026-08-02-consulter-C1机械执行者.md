# 2026-08-02 · consulter · 给 C1（单文件行数）补机械执行者

## 先更正 CFO 的诊断：C1 **有**执行者，而且它一直在发绿灯

CFO 的判断是「C1 从 2026-07-29 落地到今天，一直是散文」。
机械核实的结论是：**比散文更糟。** `scripts/gates/run-gates.sh` 里
一直有一道「单文件行数」gate，每次运行都打印 `✅ 无超限文件（或已豁免）`——
而它从来没看过 `scripts/selftest.sh`。

两个**互相独立**的原因，任何一个单独存在都足以让它全瞎：

| # | 病根 | 证据 |
|---|---|---|
| ① | `tracked` 用 `[ -d code ]` 判仓型；**框架仓的 `code/` 也存在**（装的是各自独立的模块仓，`git ls-files` 本来就看不见），于是三道 gate 只扫 `code/_template` 下 26 个文件 | `git ls-files -- code \| wc -l` → 26；全仓 259 |
| ② | 扩展名白名单只认 `py js mjs cjs ts tsx html css vue svelte` —— `.sh` `.md` `.json` 全不看 | 把 ① 修好后单加回 ② ，扫描数从 238 掉到 3 |

**这不是"没有这道门"，是"这道门永远给同一个答案"** —— 判例库「恒定答案类」
的第六种形态，也是第二次以「✅ 无超限文件」的字面形式出现。

顺带：同一个 `tracked` 还喂着「禁默认值」与「禁止路径」两道 gate，
它们在框架仓同样只看那 26 个文件。修 `tracked` 是修类，不是修实例（铁律 23）。

## 做了什么

### 一、`tracked` 改用公共件判仓型

```bash
_pl=".../lib/paths.sh"
[ -f "$_pl" ] || { printf '❌ 缺 scripts/lib/paths.sh …拒绝以「什么都没扫」的姿态报绿\n' >&2; exit 2; }
. "$_pl"
if repo_is_module; then mapfile -d '' tracked < <(git ls-files -z -- code)
else                    mapfile -d '' tracked < <(git ls-files -z); fi
```

`repo_is_module` 是判例库指定的公共件（「新写任何 check 先问我在哪种仓」）。
`|| exit 2` 是刻意的：本轮我同时在审 CFO 的判据，发现**十一条 check 里有九条**
在 `lib/paths.sh` 缺失时静默退 0，run-gates 不能再添一个。

### 二、行数 gate 按 C1 原文实现三档

- `≤500` 常态
- `501–1000` **必须在某份 tracked `report.json` 的 `oversize_files[].path` 里被点名**，
  点不到就是红（不是警告——C1 说"必须记"，只警告等于"不记也行"）
- `>1000` 硬拦，「没有说明余地」

**豁免只有两类，都不是名单**：
- *判据不适用*：二进制 / `*/vendor/*` `*/node_modules/*` `*.min.*` / **保险柜原件**
  （同目录 `SHA256SUMS` 守着的上游固化物，铁律 22 —— 拆一行校验和就废，
  "删除前唯一的保险"当场变假）。**跳过多少个会打印出来**，不静默。
- *D2/D14 存量导入*：**文件顶部 20 行内**写「下次重构拆掉」→ 只警告不拦。

旧的 `review/reviewcode/size_exempt.txt` 不再被读（gantt 那两条 vendor min 文件
已被路径类覆盖）。**但不静默作废别人的豁免**：名单里若还有两类都盖不到的条目，
逐条报红要求先迁移再删名单。

### 三、gate 必须打印被验对象

```
扫描 238 个文本文件（跳过 21 个：二进制/第三方产物/保险柜原件），存量导入 0 个
```
上一版能哑四天，恰恰因为它只印一个 ✅ 而不说扫了什么。

## 反向验证抓到了我自己写的一条恒真断言

C 那一发第一次跑是**绿的**。原因：我把子断言写成
`case "$_o62a" in *"扫描 "*)`，而 `sed -n '/单文件行数/,/gitleaks/p'`
的**末行**是 `── gate: gitleaks 密钥扫描 ──`，自带「扫描 」两个字。
删掉打印行照样匹配得上 —— 一台在验不存在机制的烟雾报警器。
改钉在只有那一行才有的 `个文本文件（跳过` 上之后，C 发正常变红。

这是判例库那句「反向验证是唯一可信的证明，看代码不算」的又一次实证，
而且这次被验出来的又是验证者自己（F7 同款）。

顺带撞出第二个：给 fixture 行加 `# ref-fixture` 标记时，脚本里有一行是
**续行 `\` 结尾**，注释被贴到反斜杠后面 →
反斜杠转义掉空格、注释吃掉换行 → 下一行 `> file` 变成一条**只有重定向**的命令，
把 report.json 截成空。**而 `bash -n` 照样报 OK。**
已改成一行并在原地写明。
