## 这是同一个形状的第五次，而且在最要命的位置

我用三轮时间批评「撒谎式成功」：install-gates 静默跳过却报已安装、
修撒谎式成功时自己撒谎、门禁红仍可推送……**每一次我都只修了被指出的那一处。**

铁律 23 是我写的：「修缺陷必须问这个形状还出现在哪」。
我写完它之后，**至少四次只修实例没扫类**。这条铁律对我自己的执行率是零。

而 `run_agent.sh` 是**派活主干**：所有派出去的活都会这样"完成"。
比前面任何一处都严重——前面的坑是某条路径上的，这条是**所有活的必经之路**。

## 修法两半，缺一不可（CFO 的判断，采纳原话）

**① 传权限参数**：`--permission-mode`（默认 `acceptEdits`，
`AIMERGENT_AGENT_PERMISSION_MODE` 可覆盖）。

CFO 提出「范围就是路签划的写区，路签已声明写边界、权限却是另一套，这两个本该是同一个东西」——
**方向对，但 harness 做不到**：它的权限模型没有「只许写这几个目录」这一档。
所以现实分工是：**harness 只管「能不能写」，路签 + `checks/_common/05` 在提交层管「能写哪儿」。**
两者仍是同一件事的两半，只是落在不同层。派活时若该角色没有路签，现在会明确警告。

**② rc=0 不能当完工**：派活前后各取一次工作树快照（`git status --porcelain` + HEAD），
**rc=0 且零改动 → 判 rc=3 未完成**，并直指最可能的原因。
这就是铁律 12「不接受口头已完成」的机械化。
只读任务（纯审阅、只出结论不改文件）用 `AIMERGENT_ALLOW_NO_OUTPUT=1` 放行，记账。

diary 现在多记 `landed` 与 `perm` 两个字段，"派出去到底落没落盘"从此可统计。

## 一处我没验、必须说清

**权限档的具体行为我没有实跑验证**——真跑会起 Claude 进程、花人类的额度，我不替他决定。
默认取了最保守的 `acceptEdits`。若 agent 报的是「不能执行命令」而非「不能写文件」，
说明 Bash 仍被门控，需换 `bypassPermissions`。

**但这次不验也不会静默失败**：landed 检查会立刻把它变成 rc=3 并打印该换哪个档。
**这正是「加断言」的价值——我不确定的地方，让机器替我确定。**

## 僵尸面板：我的冒烟测试留下的（人类发现）

人类打开 `http://127.0.0.1:8787/` 看到数据不更新。查出来：
**我做冒烟测试时在临时 clone 里跑了 `install-gates.sh`，它顺手把面板装成服务并启动了**，
那个进程一直占着 `127.0.0.1:8787`，服务的是 `/tmp/.../scratchpad/nm/ws` ——
一个早就废弃的目录，数据停在前一天 14:40。真面板在 tailnet 地址上，一直是好的。

两个层面的问题：
1. **我的**：跑会安装服务的脚本时没清场。测试用 `--no-service` 才对。
2. **框架的**：面板不同实例绑不同地址（127.0.0.1 vs 100.107.33.121）**不会端口冲突**，
   于是两个实例并存、毫无提示，人打开哪个全凭运气。

已修：
- `control-panel/install.sh` 装之前显式查有没有别的实例在跑，有就列出来警告。
- 面板页把**仓根提到标题行**（原来藏在小字里），并在时间戳后写明
  「超过 5 分钟未更新说明服务停了或你连错了实例」。

**一般化**：**任何"不显示自己在服务什么"的界面都在骗人**——
这和「门禁绿不等于验过」「rc=0 不等于干完了」是同一条：
**成功的外观必须携带它成功了什么的证据。**

## 第二批（CFO 实证驱动）：landed 恒真 + 模块门禁恒红

**① landed 恒真** —— 快照用 `git status --porcelain`，而 `run_agent`/`emit.sh` 自己往
`logs/diary.jsonl` 追加事件；模块 `.gitignore` 又不忽略 `logs/`，于是只写一行 diary
就让快照变化。CFO 实证：agent 一个字没改 run_all.sh，landed 判 true。
修：快照排除 `logs/`；模块 gitignore 补运行时产物。

**② 模块门禁恒红** —— 我把 `check-references.sh` 接进了 `run-gates`，
**却忘了把它加进 `install-gates` 的拷贝清单**，模块里恒报「缺少 check-references.sh」。
又是"加了东西没接到安装路径"。修：补进 required 与拷贝列表（连同 doc-path-exempt / doc-map）。

**③ 判据仓型不匹配** —— 补装之后模块里跑起来了，但**照框架仓写的判据在模块里恒红**
（模块没有 `agents/`，也只装门禁子集）。判据本该是「这个引用能不能在**够得着的地方**解析」，
不是「一定在本仓」。改成仓类型感知：本仓找不到就到 `.aimergent-framework` 声明的框架根找。
现在框架仓与模块仓都绿，且输出会标明自己在哪种仓里跑。

三条是同一个类：**一条永远给同一个答案的检查，等于没有这道门。**
已进判例库，并给了审核用的追问句式：
**它在什么情况下会永远通过？永远失败？** 两个答案都必须是"没有这种情况"。

**CFO 的 R3 反向验证（放入违规→变红，拿走→复绿）是唯一可信的证明。**
它对三个模块都做了，我对自己新加的检查没做过 —— 这是我下一步该补的。
